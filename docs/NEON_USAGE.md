# 运营仪表盘：Neon 流量、数据库费用与 AI 费用

后台入口：**管理后台 → 运营仪表盘**（`/admin/dashboard`）。顶部展示本账期累计、今日待结算状态、昨日估算及账期剩余额度；中部展示每日流量趋势、额度环形图和采样状态；底部提供可滚动的每日明细。支持最近 7 天／30 天切换，仅筛选已读取的记录，不另行请求 Neon。日期按柏林时区划分。只有管理员可以查看；本地开发继续沿用现有本机访问规则。

Neon 监控区覆盖项目全部分支的出站流量与数据库费用估算，不是网站访问量或 Vercel 页面带宽。AI 费用区另外读取当前环境的费用账本聚合。读取页面只读取保存的 Neon 快照和 AI 账本汇总，不调用 Neon 或模型，也不因页面停留而反复请求 Neon。费用区域展示套餐、统计截止时间与明细，并区分 Free 套餐规则、按官方用量计算的估算和暂不可用状态。

## 数据来源与计算口径

流量采样请求固定的 Neon 官方接口 `GET https://console.neon.tech/api/v2/projects/{project_id}`，读取 `data_transfer_bytes` 与账期起止时间。费用采样再根据该项目返回的 `org_id` 查询组织套餐和付费消费记录；不接受浏览器传入任意组织、项目或接口地址。API Key 只在服务端使用，不传到浏览器；不会使用 SQL 连接或迁移角色。

Neon 说明项目累计指标是近似值，每 15 分钟更新一次，最多约一小时后才可读取，不作为精确账单。官方按日历史 Consumption API 仅支持符合条件的付费套餐；当前方案通过累计值快照计算日增量，Free 账号也须先用实际凭据核对字段可读性及其与控制台的一致性。[累计指标说明](https://neon.com/docs/guides/consumption-limits)、[项目详情 API](https://neon.com/docs/reference/api/projects/get-project)、[历史接口限制](https://neon.com/docs/guides/consumption-metrics)。

- 每天 `Europe/Berlin` 时间 00:00 计划采样，结算刚结束的上一日：日流量 = 次日零点累计值 − 当日零点累计值。同账期内不再要求白天连续的小时样本；自动适配夏令时的 23／25 小时日。当天始终显示“待结算”。
- 采样时间是本系统取回指标的时间，不是供应商精确计量的截止时间。因此页面使用“估算”标识。
- 首次采样建立基线，取得相邻两日零点附近样本后才能结算。首次采样前的历史、漏掉整日的零点基线不能补造，也不能填 0。
- 跨月账期归零、累计值回退及缺少可靠零点基线时，当日保留缺失值，不把多天流量强行归到最后一天。
- 日期边界取前后 90 分钟内最近的样本，以容忍调度延迟。日内没有样本不影响两端累计值相减；已有样本若显示账期变化或累计值回退，则拒绝计算。超过 90 分钟的迟到样本不能冒充零点基线。
- 今日尚未结束，等待次日零点结算；快照过期判断同步改为每日周期，并给零点任务 90 分钟延迟宽限。手动采样可更新累计值，但不会提前结算当天。

## 数据库费用

费用是**数据库用量估算，不是供应商实际账单**。截至 2026-11-02 核查的公开 Neon API 提供用量与组织套餐，未提供本功能可调用的美元发票接口。实际已出账金额、付款与账户调整应在 Neon Console → Organization → Billing 核对。[账单管理](https://neon.com/docs/introduction/manage-billing)

### 套餐与接口

- 采样器从已核对的项目读取 `org_id`，调用 `GET /organizations/{org_id}`，核对返回组织及其 `plan`。不新增组织 ID 环境变量。公开合同中 `plan` 与消费记录的 `period_plan` 都是字符串；本版本只识别确切的 `free`、`launch` 和 `scale`，不猜测别名或未来套餐的价格。[组织接口](https://neon.com/docs/reference/api/organizations/get-organization)
- 当前套餐确认为 `free` 时，展示当前 Free 套餐的零费用规则，不调用需要付费套餐的消费历史接口。这不证明本账期较早时间没有付费使用，也不是从发票读取 `$0`。无法核对套餐时显示未知，不退回 Free。
- Launch／Scale 使用 `GET /consumption_history/v2/projects`，固定目标 `project_ids`，查询 `org_id`、`from`、`to`、`granularity=daily` 和下表八项 `metrics`。返回路径为 `projects[].periods[].consumption[].metrics[]`，按 `metric_name` 与 `value` 读取，并核对项目、`period_plan`、日期窗口和响应结构。[消费接口](https://neon.com/docs/reference/api/consumption/get-consumption-history-per-project-v2)
- 不支持的套餐、混合计费分段或套餐变化、组织不匹配、权限不足、缺失的日期窗口及无效数值均显示费用暂不可用，不能当作零。接口允许在有效时间段中省略零值指标；这不等于允许把缺失的整个项目或整天补零。[消费指标说明](https://neon.com/docs/guides/consumption-metrics)

### 费用口径与价格版本

按 **2026-11-02 核对的公开 Launch／Scale 价格**计算以下七类数据库费用。单价、分支包含量及单位换算随代码版本维护；套餐调整后须重新核对。1 GB 为十进制 `1,000,000,000` 字节。[当前套餐价格](https://neon.com/docs/introduction/plans)

| 费用类别 | 消费指标                                              | 换算与扣减                                               | Launch                               | Scale                                 |
| -------- | ----------------------------------------------------- | -------------------------------------------------------- | ------------------------------------ | ------------------------------------- |
| 计算     | `compute_unit_seconds`                                | 除以 3600，得到 CU 小时                                  | $0.106／CU 小时                      | $0.222／CU 小时                       |
| 数据存储 | `root_branch_bytes_month`、`child_branch_bytes_month` | 分别除以 `1e9`，得到 GB 月，再汇总                       | $0.35／GB 月                         | $0.35／GB 月                          |
| 恢复历史 | `instant_restore_bytes_month`                         | 除以 `1e9`，得到 GB 月                                   | $0.20／GB 月                         | $0.20／GB 月                          |
| 快照存储 | `snapshot_storage_bytes_month`                        | 除以 `1e9`，得到 GB 月                                   | $0.09／GB 月                         | $0.09／GB 月                          |
| 公网传输 | `public_network_transfer_bytes`                       | 项目账期累计 GB 扣除 500 GB 包含量，最低为零             | $0.10／GB                            | $0.10／GB                             |
| 私网传输 | `private_network_transfer_bytes`                      | 除以 `1e9`，得到 GB                                      | 不支持                               | $0.01／GB                             |
| 额外分支 | `extra_branches_month`                                | 每个时间段的子分支小时数扣除包含量，最低为零，再除以 744 | 每小时包含 9 个子分支；$1.50／分支月 | 每小时包含 24 个子分支；$1.50／分支月 |

V2 名称带 `bytes_month` 的存储指标已经是 byte-months，**不能再除以 744**。只有旧项目详情中的 `data_storage_bytes_hour` 才是 byte-hours，而且混合数据存储与恢复历史，本功能不用它代替 V2 费用明细。`extra_branches_month` 的原始单位则仍是分支小时，并非已经扣除免费分支后的数量。日粒度下的分支费用是估算，不能保证与供应商逐小时计算完全一致。[官方换算规则](https://neon.com/docs/introduction/usage-calculations)

费用统计仅覆盖**本账期已经结束的完整 UTC 日期**，截止为最近一次采样所处日期的 `00:00 UTC`，不包含当天尚在增长的用量；账期首日可能没有完整日期可统计。流量图仍按柏林日期归集，两者不强行按同一日对齐。页面必须显示费用自己的起止时间和采样时间，不能将这部分费用称为实时账期总账单。

统计范围不包含 Neon Functions、Auth、Object Storage、AI Gateway，亦不包含 Vercel、外部 AI 服务、税费、折扣、抵扣、合同定价或组织级最低收费／实际收款调整。公共网络计量可能包含同一项目其他产品的共享流量，因此也不能将网络费用解读为仅某张业务表的费用。小于实际收款门槛的用量费用仍可出现在估算中。供应商发票是最终依据。

费用读取失败不伪造零值，也不应阻止已经通过校验的流量样本保存。每次采样的费用摘要与该流量样本一同持久化；旧样本没有费用字段时继续可读，显示尚无费用记录。刷新记录、切换 7／30 天视图和打开页面均不会额外访问计费接口。

## AI 调用费用

展示今日和本月截至读取时刻的已记账费用、未结额及五类明细：信号生成、候选补全、自动采集、专题洞察、连接能力测试。按现有账本的 **UTC** 预算归属日汇总（生成、补全、采集、洞察用 `budget_day`；连接测试用 `created_at` 的 UTC 日期），不能与柏林日期流量直接对齐。生成、补全、采集和洞察仅统计当前管理员的任务；连接测试没有所属用户字段，单独标注为全站测试。页面不会把 Neon 估算和 AI 记账相加成一张账单。

已记账金额沿用原执行器保存的结果：有 API 费用回执时优先使用回执，否则保留原估算；旧记录没有费用来源凭证时不臆造“实际费用”。尚在排队、运行中或结果未知的预留单独展示为未结额，不当成已经花费。确认拒绝且原账本已记零的记录仍为零。本页只读分类汇总，不修改或重新结算旧账目。

汇总覆盖所选月份的完整账本，不受任务列表最近条数限制，也不会因任务在界面中隐藏／软删除而丢失费用。模拟生成记录不算真实 AI 花费。本地读取本地数据库，生产读取生产数据库，彼此不自动合并。若某个账本未配置或无权限，单项显示暂不可用，总额标明“已知小计／数据不完整”，不能以零代替缺失。

复用现有生成、自动化和 AI 配置角色，以只读事务做 SQL 聚合；不读取原文、候选内容、API Key 或模型请求。AI 汇总不写入共享 Neon Blob，也不增加任何迁移或角色授权。打开页面和“刷新记录”会读取一次汇总，页面不轮询，不调用模型。已有业务连接配置正确即可显示 AI 费用，不依赖 Neon 监控密钥。

## 存储

生产使用独立配置的私有 Vercel Blob，每次新样本写入时保留最近 60 天的有界滚动快照；关闭采样后不会继续自动清理。包含费用摘要的历史最多 6000 条、总计不超过 8 MB。条件写入通过 ETag 防止定时与手动采样并发覆盖，读取跳过旧缓存。快照只保留监控所需字段和费用摘要，不保存完整 Neon 响应、组织详情、密钥、数据库连接串或业务内容。

严格本地开发模式使用 `.hzense-local/neon-usage/<project-id>/` 中的不可变样本文件，不使用生产 Blob。文件通过原子创建保存，不依赖重启后可能残留的锁文件。该路径不提交 Git；本地数据不是线上数据的自动副本。读取 Neon 指标仍需单独配置 API Key，本地 PostgreSQL 没有可冒充的 Neon 用量。启动入口继续遵守现有本地隔离规则，不复制生产环境文件或生产数据库凭据。

启动 `pnpm local:dev` 前，可在当前进程环境中明确提供 `HZENSE_NEON_PROJECT_ID`、`HZENSE_NEON_API_KEY` 和可选额度变量；开发启动器仅透传这三项监控设置，不继承云 Blob 或派发令牌。未配置时后台显示缺项。本地采样通过页面手动触发，GitHub 每日调度始终只请求线上正式域名。

本功能不新增业务表、不执行数据库迁移或角色授权。启用前需准备监控专用凭据；开发代码存在不代表生产配置已完成。

## 配置

以下变量均为服务端变量，不加 `NEXT_PUBLIC_`。Production 凭据不配置给 Preview；开发环境单独配置。示例文件只保留空值。

| 变量                            | 用途                                                                 | 配置位置                                                             |
| ------------------------------- | -------------------------------------------------------------------- | -------------------------------------------------------------------- |
| `HZENSE_NEON_API_KEY`           | 可读取目标项目详情、所属组织套餐及适用的消费记录；仅用于固定只读接口 | Vercel Production Secret；本地单独提供                               |
| `HZENSE_NEON_PROJECT_ID`        | 要监控的 Neon 项目 ID，不是分支 ID 或数据库主机名                    | Vercel Production Config；本地单独提供                               |
| `HZENSE_NEON_USAGE_BLOB_TOKEN`  | 监控快照所在私有 Blob Store 的服务端令牌                             | Vercel Production Secret；本地文件模式不需要                         |
| `HZENSE_NEON_USAGE_CRON_SECRET` | 至少 32 字符、无空白的专用派发令牌，与其他任务令牌分开               | Vercel Production Secret 与 GitHub 仓库同名 Actions Secret，值须一致 |
| `HZENSE_NEON_USAGE_QUOTA_BYTES` | 可选的本账期流量额度，单位为字节；未配置时不显示额度占比或阈值提示   | Vercel Production Config；本地可选                                   |

额度应按当前套餐及项目实际额度填写，不能把数据库存储大小填入此项，也不默认将某个历史套餐额度写死。页面的额度提示只用于观察，不会暂停数据库、停止业务任务或修改 Neon 配额。

## 定时与手动采样

`.github/workflows/neon-usage.yml` 使用 UTC 22:00／23:00 两个候选计划，根据柏林当前夏令时偏移只选择对应本地 00:00 的一次执行（夏季 UTC 22:00，冬季 UTC 23:00），固定向 `https://hzense.com/api/internal/neon-usage` 发起带专用令牌的 POST。工作流不检出仓库、不执行依赖安装，不持有 Neon 或 Blob 凭据；只持有采样派发令牌。日志不输出响应正文或请求头。

GitHub 仓库变量 `NEON_USAGE_MONITOR_ENABLED=true` 才启用定时任务，默认缺省关闭。工作流只允许在 `main` 运行；手动 **Run workflow** 可在定时开关关闭时进行一次验收。后台“立即采样”与定时入口共享保存逻辑，最短采样间隔为 15 分钟，短时间重复请求不会人为增加采样密度。

GitHub 定时任务是尽力执行，可能延迟或跳过，不应视为精确计量时钟。缺口必须在后台可见。继续沿用 GitHub 调度，不增加 Vercel Cron。[Vercel 官方限制](https://vercel.com/docs/cron-jobs/usage-and-pricing)。

## 启用与验收

1. 合并并部署代码，保持 GitHub 定时开关关闭。在 Vercel 配置上述必要变量，确认正式域名加载对应部署。
2. 打开 `/admin/dashboard` 检查配置状态；缺项时应明确提示未配置，不能显示合成流量。
3. 手动采样一次，将项目、本账期和累计流量与 Neon Overview → Usage 对照。该核对仅验证当次字段读取，不补造历史数据。
4. 核对费用显示的套餐与组织一致。Free 应标明套餐规则；付费应标明 UTC 完整日估算与各项价格，组织权限不足或套餐不支持时保留流量数据并显示费用原因。
5. 重新打开页面确认快照仍在、采样时间正确，且未输出密钥。取得相邻两日零点附近样本后再核对上一日增量。
6. 在 GitHub 手动运行 `Neon network usage sampling`，核对运行结果及后台最近采样；通过后再设置仓库变量 `NEON_USAGE_MONITOR_ENABLED=true`。
7. 之后观察跨日连续数据与缺口提示。关闭仓库变量会停止后续定时派发，已保存的快照仍可查看。
