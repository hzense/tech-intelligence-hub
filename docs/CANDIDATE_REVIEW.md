# 候选审核与正式发布

## 通用补证与登记（2026-09-24）

新增候选级补证请求、独立签名材料报告与确认登记入口。原候选不变，登记不等于发布；生产默认关闭，外部核验服务尚待接入。使用方法、角色及上线门禁见 [通用材料登记](MATERIAL_REGISTRATION.md)。

## 正式发布材料包（2026-09-24）

### 补证补全展示衔接（2026-09-25，代码修复，部署另验）

当正式材料尚未就绪时，页面读取与当前候选绑定的最近补证请求（最多十个）中的最新已完成补全任务，重新核对原文引用与启用领域后展示人物、组织、领域及证据，标注“已补全，待核验登记”。组织名称已提取但类型依据仍为空时单独提示，不再把已提供的人物和领域显示为未找到。登记前审核版本的缺项检查折叠展示，明确它与补全提案不是同一状态。

“刷新补证状态”同时更新上方材料，重新打开页面也读取保存结果；不重新调用 AI。补全预览独立于发布判定，不改变 `ready`、`preparationHash`、正式实体或证据。正式材料已经就绪时优先展示确认实际使用的材料，不能以未登记提案替换待确认版本。核验登记完成后恢复正式材料展示。无需数据库迁移、角色授权或新环境变量。

任务内候选页新增“正式发布材料”：集中展示当前候选标题与摘要、事件日期及原文依据、人物的事件角色与组织、实际命中的正式实体、领域、逐条主张与公开证据来源。技术 ID 收在可展开的关联记录中，不要求管理员填写。缺少人物、未建档、同名歧义或公开证据缺失时保留具体补证要求，不生成虚构关联，也不会自动将上传原文登记为公开证据。

材料与已有的确定性准备共用实体和证据匹配规则。证据必须来自活跃来源且已登记为 `verified`，链接须为 HTTPS、无账号密码及片段，并符合来源的 `allowed_hosts`；同一主张的全部引用必须唯一命中同一证据。该匹配不代表已完成事实、来源许可、人物身份或反证的独立核验。

“确认候选并送核验”只提交服务器生成的材料指纹 `preparationHash`，不提交浏览器编写的材料。服务端重新准备并比对；名称、实体、领域、证据或补全提案变化时，须刷新阅读后再确认。审核记录以系统备注 `publication-materials-v1:<hash>` 保留确认指纹；原始候选、费用与历史修订不覆盖。老页面缺少新指纹会拒绝确认，刷新页面即可加载新协议。

确认响应丢失时，当前页面重试保留原请求编号、原预期修订和材料指纹；即使读取到已保存的新审核版本，也不自动改为创建下一版。明确冲突会要求刷新；网络异常或未知提交不能当成未写入。

目录读取采用只读一致性快照，并顺序使用同一 PostgreSQL client。证据查询达到截断上限、补全记录读取失败或已完成补全损坏时停止准备，不将“读不到”解释为“没有”，也不将截断后的单条结果当成唯一匹配。刷新和阅读不写库、不调用 AI。

本批不增加迁移、角色权限、模型调用或生产发布。**尚未实现缺失正式实体的登记入口、公开证据登记与许可核验执行器；缺项仍需先完成正式目录/证据准备。材料包可读、可确认不等于生产候选已经具备发布资格。** 后续仍须完成真实样本的登记、独立核验、发布、公开搜索及撤回验收。

开发验收：Web 单元/服务边界测试、类型/Lint 与 Chromium 合成页面回归覆盖材料关联、转义、同名歧义、来源域名限制、读取失败、指纹变化及未知提交的同编号确认；不代替生产验收。CI 显式启用候选页面 Chromium 测试，以及使用 `HZENSE_CANDIDATE_REVIEW_SQL_TEST_URL` 与 `RUNTIME_READER_TEST_ISOLATED_CLUSTER=1` 的原生 SQL 回归。SQL 测试只允许隔离本地集群，创建并清理独立合成数据库，不能指向开发或生产业务库。本机初始化文件缺失时该 SQL 测试未执行，须以本次 CI 的独立步骤结果为准。

## AI 补全执行器（2026-09-23，本地开发）

候选页在确定性检查发现“缺少事件日期”或“完全缺少关键人物”时，可由管理员显式确认启动一次 AI 补全任务。执行器复用当前生成 Profile 的 `verify` 阶段、连接能力证明、单批／UTC 日预算、Vercel Workflow 与隔离 Sandbox；任务先持久化，再进入队列。实际模型调用所在步骤禁止自动重试，未知结果保留任务和预算供人工对账。

补全器只能提议事件日期、关键人物和组织，且日期和人物必须附原文逐字引用。标题、摘要和主张由服务端锁定；模型不能创建实体 ID、领域、公开证据、核验结论或发布许可。保存前重新执行结构、字数、日期和原文证据校验；完成后再用正式实体目录、启用 Taxonomy 与已核验公开证据重新准备审核。名称未命中正式实体或公开证据缺失时仍然阻断发布，不允许重复调用 AI 假装解决目录问题。

任务记录由 `0022_candidate_enrichment_runs.sql` 保存，沿用 `hzense_generation_admin`，但必须通过 `db/roles/upgrade_candidate_enrichment.sql` 精确增加新表列权限。生产迁移、授权、配置或付费验收不在本地开发内；未完成这些步骤时页面不得宣称补全可用。

## 交付范围（2026-09-21）

入口仍为 AI 生成任务内逐条“审核候选”，地址 `/admin/signal-review/{任务 ID}/{原始候选序号}`。没有独立审核工作台。原始生成结果不覆盖；候选页不再提供标题、摘要、日期、实体 ID、证据 ID、事件键或审核意见等人工填写项。

正式发布区采用确认式操作：系统自动读取最新审核、核验、组装及发布状态，并自动绑定核验记录、审核修订和发布修订。管理员不修改候选内容、不粘贴签名 JSON、不复制 UUID、不填写版本号或技术原因，只确认当前允许的下一步。尚无审核记录时，服务器根据当前候选与正式目录生成第一版审核快照；只有人物／组织唯一命中、领域规则命中且每条主张唯一命中已核验公开证据时，才显示“确认候选并送核验”。页面以状态表逐项展示事件日期、人物、组织、领域和每条主张公开证据的“已匹配／待补全／需消歧”结果；未满足条件时不渲染空白表单，也不能绕过门禁。

本次交付代码、隔离数据库回归和生产验收清单；**不等于生产已启用**。未执行生产迁移、角色授权、公开数据源切换或真实 AI 调用。

## 操作顺序

1. **核对并确认系统准备结果**：管理员阅读候选、主张、原文证据和关联信息，不填写修订字段。服务器使用正式人物／组织实体、启用的 Taxonomy 与已核验公开证据自动生成审核快照和稳定事件键；所有依赖唯一匹配时，管理员只需确认送核验。任一依赖缺失或歧义时，页面只显示阻塞原因，不提供越过门禁的确认按钮。
2. **转换正式私有候选**：只接受最新送核验修订，引用已登记且已核验的公开证据和稳定实体。事件键冲突不静默合并；转换仍不公开，私有原文不会自动复制成公开证据。
3. **提交可信签名报告**：独立核验方检查事实、参与人物、组织、公开许可及反证，签署完整材料绑定报告。浏览器不能直接提交可信布尔值，管理员审核不是事实核验通过。
4. **组装、发布或撤回**：组装引用既有核验记录，生成新版本；正式发布单独确认，服务端实时核对授权任务、租约、发布修订、有效期及依赖。撤回保留历史与回执，不依赖生成/审核写开关；可针对历史转换修订撤回，不能以最新拒绝记录阻止紧急撤回。
5. **检查公开结果**：成功回执后仍需核对公开列表、详情、搜索和撤回结果。页面阶段回执不是永久发布许可；依赖失效或过期仍可使内容退出公开读取。

已发布版本撤回后若需重发，系统必须从当前候选和正式依赖重新生成下一审核修订，再次确认、转换并完成独立核验；不能用同一已消费组装记录新建请求重复公开。同编号重试只用于取回原操作回执。只读检查可选择历史审核修订，不因最新修订被拒绝而隐藏原发布状态。旧的浏览器自填审核保存动作不再由 API 接受。

确认操作不自动调用 AI。系统准备是确定性的候选转换，不是事实核验：名称必须唯一命中正式实体；领域仅从启用分类的受控关键词规则产生；每条主张必须含有原文引用，且全部逐字引用必须唯一出现在同一条已核验公开证据中。空引用不能命中任意目录证据。页面不会把私有引用自动变成公开证据，也不会把人物名称自动当成已消歧实体。新公开证据／人物登记、独立核验方实际运营及生产授权仍是外部前置条件。

## 存储与安全边界

- `0020_candidate_reviews.sql`：追加式 `candidate_reviews` 和 `candidate_review_conversions`；绑定 owner、任务、原序号、原材料哈希及审核修订，幂等请求和比较后写入。
- `0021_candidate_review_attestations.sql`：追加式 `candidate_review_attestations` 保存签名审计；提供专用锁函数，复用已有封存、核验和发布机制。
- 删除生成任务与审核写入共用任务锁；已删除/变更材料不能继续审核或发布。历史发布撤回路径仍保留，已删除任务可通过既有受限撤回服务处理。
- 审核、转换、核验、发布控制、Publisher 分角色连接，逐次检查真实数据库能力；不使用 migrator 作为运行账户，不退回宽权限连接。
- 核验记录写入与签名审计同事务；组装和发布为后续独立事务，不能把未提交材料当成封存证据。
- 操作失败不自动重试、不丢弃历史费用、不返回数据库连接信息、签名密钥或私有未引用原文。

## 签名报告协议

提交信封为 `{keyId, payload, signature}`；`payload` 是原样 JSON UTF-8 字节的标准 Base64，`signature` 是对原始字节的 Ed25519 签名（标准 Base64）。不得解析后重新排版再验签。

Payload 精确字段为 `version: "signed-candidate-verification-v1"`、`runId`、`candidateIndex`、`reviewRevision`、`materialHash`、`issuedAt`、`ingestBefore`、`verification`、`rationale`。接收窗口最长 60 秒；与核验记录自身 TTL 是不同约束。`verification` 使用既有 candidate-verification-v1 契约，绑定正式快照、bundle 指纹及可信 verifier ID；`rationale` 为六项检查的逐项理由。额外字段、过期、错配、无效签名一律拒绝。

网站**没有**签名私钥，也不会自动生成“通过”报告。此协议接入可信核验结果，不意味着已实现或启用自动事实核验执行器。独立核验方必须实际核验，签名仅证明报告来源。

## 隔离验收记录

以下为补全执行器开发前的隔离验收记录：使用本机一次性 PostgreSQL 18.4 + pgvector 测试集群、合成候选与测试密钥，不读取生产资料、不调用供应商模型。当时完整 Schema 为 22 个迁移、51 张表；新增 `0022` 后为 23 个迁移、52 张表，需另行验收。

验证结果：Web 默认测试 526 通过、9 项可选环境测试跳过；数据库默认测试 2121 通过，另行启用完整迁移链 677 项全部通过。实际组件 Chromium 合成浏览器场景单独开启通过，覆盖桌面/390px 窄屏、保存刷新、409 保留输入、网络未知同编号重试及历史撤回。类型、ESLint、格式检查及生产构建通过。默认环境跳过不计作实际验收成功，数据库与浏览器通过项均来自显式开启的独立运行。

- 审核：owner 隔离、材料哈希复检、CAS 并发冲突、追加式历史、删除互斥、固定请求幂等。
- 转换：既有公开证据和实体校验、事件去重、同候选新审核追加版本、旧材料不可覆盖。
- 发布：真实专用低权限角色完成核验/组装/发布；模拟提交成功但响应丢失，原编号重试不增加 outbox。
- 搜索：直接使用应用 `publicSignalSearchQuery`，发布后命中，人物依赖变化后消失，恢复依赖不自动复活，修订后重新核验可再发布，撤回后消失。新版 Signal 搜索直接使用 `current_public_signals`，不是改写旧 FTS 投影表。
- 权限：额外表/列/函数权限、核验不可变保护失效均拒绝；角色脚本未在生产执行。

这些结果不是生产验收；上方生产清单仍未执行。

### 补全执行器发布前验收（2026-09-23）

新增 `0022` 后，在一次性 PostgreSQL 18.4 + pgvector 集群中重新跑通完整迁移集成测试链，完整结构核验为 23 项迁移、52 张表。另以真实低权限账户执行补全 ACL 升级及任务生命周期测试：原 51 项列权限升级为 96 项，创建幂等、重复领取拒绝、跨 owner 隔离、供应商返回零费用、完成后禁止二次提交、无效私有结果拒绝以及禁止删除/修改快照均通过。测试不调用真实 AI、不修改生产数据库。
