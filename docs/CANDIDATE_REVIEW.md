# 候选审核与正式发布

## 当前交付：审核准备工作台（2026-09-21）

统一入口为 AI 信号生成页 `/admin/signal-generation`，从任务内候选卡片打开逐条材料页 `/admin/signal-review/{任务 ID}/{原始候选序号}`。序号从 0 开始，保持生成结果原序号；部分候选被拒绝后不重新编号。独立工作台及汇总入口已移除，旧 `/admin/signal-review` 地址鉴权后跳转至 AI 生成页。

生成任务列表展开的候选卡片、任务详情页的每条候选均提供“审核候选”直达入口。仅完成任务且带有效原始序号的私有待审核候选显示入口，目标页仍执行独立鉴权和材料复检。材料页返回原任务或 AI 生成任务列表，不复制候选或保存第二份数据。

本批是第一阶段的只读开发，不是已打通审核发布闭环：

- 复用生成任务入口，不另行查询跨任务审核列表。
- 只接纳完成且未删除任务的私有待审核候选，重新验证原文快照哈希、现行结构、字符限制及逐字引用。
- 展示正式信号式正文、人物建议、证据与引用所在完整片段；不暴露连接／模型快照、租约、归属标识或未引用的原文片段。
- 从材料重新计算缺项，不信任模型或历史 `issues`；明确公开来源、独立核验、人物组织绑定、事件身份、领域分类与发布链路待办。
- 页面独立验证管理员会话，存储按 owner 查询，使用只读事务。生成开关关闭时仍可核对材料；不依赖模型凭证或发起 AI 请求。
- 不保存人工决定、不改写历史结果、不新增核验记录、不发布。发布按钮明确禁用，材料指纹只是后续绑定基础，不是许可。

旧候选不符合当前规则时保留原任务，不自动修正文案或提升资格。材料页的待办不是内容质量评分，也不是已查询所有正式实体后给出的最终诊断。

## 后续按顺序开发

1. 人工审核记录持久化：独立私表、候选及材料指纹绑定、修订比较、幂等请求、审核历史、待补证／拒绝／送核验。人工决定不直接改成 verified。
2. 私有候选转正式候选适配：登记公开来源及证据、人物／组织消歧与稳定实体绑定、Taxonomy、事件去重及不可变版本。
3. 可信核验执行器：原文使用许可、独立来源与反证检查；结果绑定完整材料，生成有时效的核验记录。不能把浏览器的布尔勾选直接传给私有可信核验接口。
4. 受控发布适配：组装、任务授权、租约、原子公开发布与安全撤回；复用既有 `0011`／`0012` 规则，不直接修改 status。
5. 独立审批生产权限／配置及读模式后，验收公开列表、搜索、撤回、依赖失效与历史资料迁移。代码交付不等于生产启用。

本批不需要迁移、凭据、生产写授权或 AI 费用。后续新增审核私表、角色权限及生产读模式切换必须分别核对、批准和验收。

## 本地验证

- Web 默认测试 505 项通过、8 项环境测试跳过；包括新增材料复检与真实组件静态渲染回归。
- 扩展已有服务适配器回归，验证跨 owner 拒绝、删除记录拒绝、关闭生成时只读审核，以及没有数据库写入或 AI 访问。数据库驱动为合成替身，不计为生产或真实 PostgreSQL 验收。
- Web 类型检查、ESLint 和差异空白检查通过。尚未执行浏览器视觉验收、PR、生产部署或真实审核发布。
