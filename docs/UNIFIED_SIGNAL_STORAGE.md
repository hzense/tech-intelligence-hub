# Signal 统一物理存储重构

2026-10-05 · 阶段 A：契约、转换与只读预演已实现；DDL、写入切换及生产迁移未实现。

## 结论

所有正式 Signal 的目标存储统一为 `signals`（身份）与 `signal_versions`（版本正文），
不再按历史导入、AI 生成、人工确认拆分主存储。**这是一项正在实施的重构，不是当前生产已完成的状态。**
现有 110 条归档和人工发布记录继续由旧路径服务；本批不改数据库、角色、生产开关或页面读取。

## 统一内容契约

实现：`packages/database/src/unified-signal-contract.mjs`。

- `title`、`summary`：新内容最多 80／500 个 Unicode 字符；历史转换保留原文，不截断。
- `type`：一个事件类型，不接受数组；旧人工记录未填类型时为 `null`，不把 `editorial` 当事件类型。
- `occurred_at`、`captured_at`：分别为事件时间、采集时间，未知时为 `null`。不能用迁移时间或发布修订时间充当采集时间。
- `confidence`：新闻可信程度，0–1 或 `null`；`importance` 为 1–5 或 `null`；`novelty` 为 0–1 或 `null`。
- 新契约不含 `strength`。旧 3.0.0 封存版本保留原字段／指纹，不直接删列破坏历史。
- `people`、`organizations`：名称、可空实体 ID、可空事件角色、可空简介及类型。人物固定 `person`；组织类型未知时为 `null`，不能一律编成公司。无证据实体关联不补造 ID。
- `topics`：多个规范领域标签，每个 ID 唯一。
- `sources`：来源 ID／名称可空，但已有来源 URL 原样保留；不把来源网站充作事件组织。
- `related_entities`：历史模型、产品、论文等关联实体，不强行归入人物／组织。
- 不收录国家领导人为人物资源；原始审计资料仍留在旧表，正文不全文删词。

来源与发布依据分开：历史 `origin=legacy_seed`、`publication_basis=legacy_import`；
AI 候选经人工确认的内容为 `origin=ai_generation`、`publication_basis=manual_confirmation`；草稿的发布依据为 `null`。
它们不能被转换成 `source_evidence`。独立证据核验仍是不同的资格，不能由内容齐全推导。

`unifiedSignalReadiness()` 只说明日期、人物、组织、领域及事件类型是否齐全，**不是发布授权**。
新版本的正式发布必须经过管理员认证、归属检查、确认动作、版本并发校验和原子提交。

## 已实现的转换与预演

`unified-signal-plan.mjs` 是纯函数，不连接数据库、不写文件、不发起 AI：

1. 校验冻结的 110 条完整归档及其原始／引用／投影摘要。
2. 将每条归档转换为一个 master 和一个 4.0.0 版本，保留 ID、日期、URL、真实评分、领域和人物组织。
3. 读取人工发布的**所有修订**，不能仅传入 `editorial_public_signals` 的当前公开行。
4. 严格复用现有 `editorial-` ID 算法；逐个保留 draft／publish／withdraw，以及撤回后再次发布。
5. 拒绝修订缺号、重复请求、归属变化、非法状态跳转或撤回时内容改变；原请求引用保留在私有版本元数据。
6. 对内容和整个计划计算 SHA-256；预演公开列表前根据原始输入重建计划，拒绝删掉撤回版本或篡改状态。

`unified-signal-preflight.mjs` 提供维护侧只读适配器：由调用方借入专用连接，在一个
`REPEATABLE READ READ ONLY` 事务中读取全部归档、人工修订及原核心表数量。
若原 `signals`／`signal_versions` 已有记录，额外报告必须对账，不能覆盖或忽略它们。
未提供自动连接、生产 CLI、后台路由或 Actions 派发入口。本批测试使用内存适配器，**没有在生产或真实 PostgreSQL 执行该新预检**。

返回明确为 `status=preview_only`、`cutover_ready=false`；摘要与含私有来源引用的完整计划分离，
完整计划不得上传公开仓库、公开日志或浏览器。历史修订时间保留微秒，不能经 JS Date 隐式截短。

### 本地验证

新版转换及只读适配器测试 22 项通过；包含全部 110 条冻结归档、完整人工修订、撤回／再发布、空值、
稳定 ID、微秒时间、计划篡改、缺号、归属变化和无私有字段公开。数据库包默认测试 2,979 项通过、
738 项环境测试跳过；类型检查、修改文件 lint、格式和差异检查通过。只读 SQL 适配器为模拟测试，
尚未执行真实 PostgreSQL 集成测试，也未连接生产。

不能在上面写入和读取两端完成前，仅把本批纯计划 INSERT 到旧表，也不能提前关闭旧路径。
切换之前可安全撤销本批代码，因为没有运行路径接入；切换之后是否能回退旧写入，必须以新修订是否已回同步为准，
不能简单切旧开关导致新发布／撤回丢失。旧表先保留为审计资料，不直接删除。

## 风险与反面观点

直接保留三套物理表、只合并视图成本较低且已经可用，但没有实现用户要求的统一主存储。
直接删除旧表或放宽所有旧约束改动更少，却可能破坏已封存证据、让撤回内容复活或伪造缺失评分。
因此选择前向、版本隔离的重构，代价是必须完成 catalog／权限／写入／读取整条链后才能切换。
当前最重要的限制是：本批只完成阶段 A，不能宣称统一数据库已上线。
