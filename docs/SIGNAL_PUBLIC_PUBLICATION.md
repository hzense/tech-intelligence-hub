# 受限公开发布与安全撤回

这是 Signal V3 的公开发布工程入口，不是 AI 采集器，也不是新的核验模型。后台认证沿用 [管理员认证](ADMIN_AUTH.md)。

## 已实现的链路

1. 可信核验阶段记录原始候选材料的核验结果；新迁移同时记录数据库依赖 seal。
2. 核验结果通过后生成并封存新的候选版本，原版本不被改写。
3. 受限 Publisher 核对组装、当前材料、核验有效期、任务授权／运行租约及预期发表修订，在一个事务内写新版本、Head、Outbox 和公开许可。
4. 网站与新版信号搜索读取 `current_public_signals`，不将新正文复制到旧 Seed 搜索表，因此不需要每次手动同步索引。
5. 管理员可以独立撤回。撤回不依赖自动发布总开关、原运行是否取消或原租约是否到期。

`current_public` 只代表该回执对应内容版本／发布修订在返回结果读取时的资格；幂等 `replay` 是历史回执，不能视为重新发布，也不会因为同信号有了更高版本就显示旧版本仍可公开。

## 后台操作

路径：`/admin`。发布表单只接受信号标识、版本、预期修订、固定原因，以及已有受控任务的运行 ID／租约持有者／隔离序号。请求号首次提交自动生成，网络结果未知时使用同一请求号重试。

接口：

- `POST /api/admin/signals/publish`
- `POST /api/admin/signals/withdraw`

两者都必须拥有当前 Google 管理员会话，并携带精确同源 `Origin` 和 JSON 请求体。匿名为 401，来源不合格为 403，字段／大小不合格为 400，未配置为 503；公开错误不带 SQL、密码或私有核验材料。

发布与撤回不是“修改某行 status”。系统会使用版本比较防止覆盖更新，写入永久发表事件。不要通过后台输入不存在的运行标识尝试创建任务；任务配置与采集器仍是后续工作。

提交确认或提交后的资格读取失败时返回 `503 publication_outcome_unknown`。这时应保留请求号重试，不能据此认定数据库已回滚。

## 新配置（本次不自动启用）

| 配置                                                              | 含义                                                                              |
| ----------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| `HZENSE_SIGNAL_READ_MODE`                                         | 缺省 `legacy` 保持旧网站；`database` 使用当前资格视图；其它值拒绝读取，不偷偷回退 |
| `HZENSE_PUBLISHER_DATABASE_URL`                                   | 独立 `hzense_publisher` 连接，不接受 `DATABASE_URL`／迁移账号替代                 |
| 现有 `HZENSE_RUNTIME_DATABASE_URL` 与 `HZENSE_RUNTIME_EXPECTED_*` | Reader 连接与已审核目标，Publisher 同样必须匹配这个生产库目标                     |

Publisher 必须是受限、`NOINHERIT`、无超级用户／创建角色／创建数据库／复制／绕过 RLS 能力的角色。连接须使用批准的 Neon pooled host、显式端口及数据库、`sslmode=verify-full&channel_binding=prefer`。凭据仅配置到 Vercel Production Secret，不写仓库，不传浏览器，不继承到 Preview。

未切换到 `database` 时后台禁止新发布，避免回执成功但网站仍用旧数据；紧急撤回不受读模式限制。读模式切换并不生成历史核验或补齐人物。

独立授权候选为 [configure_signal_publisher.sql](../db/roles/configure_signal_publisher.sql) 和 [configure_public_signal_reader.sql](../db/roles/configure_public_signal_reader.sql)，须在完整 schema 审核之后，由指定所有者在批准窗口执行。脚本不替操作者创建角色或密码，不自动清理环境 `PUBLIC` 权限。

新版 Reader 增量核验为 [verifyCurrentPublicSignalReaderAccess](../packages/database/src/current-publication-reader-contract.mjs)。它检查当前数据库里的 V3 应用能力；不能代替完整 schema／函数正文／owner 检查及旧跨数据库与 provider ACL 审计。旧预检的结构目录精确识别新增视图及函数，但旧 FTS ACL 契约仍拒绝授予 Runtime 新视图 `SELECT`／资格函数 `EXECUTE`，不能把它原封不动用于切换后的 Reader。生产切换前必须先保留旧审计证据，再审核 V3 增量及完整生产兼容性。

应用每次取 Publisher 连接核对登录身份及高权限标志，但不在线枚举全部 ACL。角色名称正确不代表权限不会漂移，生产最小权限必须独立审查并持续维护。

## 失效与迁移

新迁移 `0012_current_signal_publication.sql` 不为历史核验记录补发许可。旧私有发表和已有 Seed 内容不能直接冒充符合新标准的公开信号。

来源、证据、人物、组织、档案或 Topic 相关材料变化后，核验 seal 永久失效；撤回／失效正文从列表、详情、关联信号和新版信号搜索中消失。恢复原值不会自动恢复可见，需要新核验及新发布。

旧雷达评分不包含内容版本和发表修订，在新读模式下暂停使用并提示待重算；趋势计算、资源排序和新专题洞察属于后续开发，不在本次自动补造。

当前实现每次依赖变更检查仍有效的核验 seal；公开视图与信号检索也有实时资格计算成本。大规模数据上线前须做真实负载验收，并评估依赖反向索引与检索索引优化，不把小型隔离测试等同生产容量证明。

## 上线顺序与证据边界

代码测试通过不等于生产已启用。上线仍需：审核并执行新迁移 → 审核并配置 Publisher／Reader 最小权限 → 配置生产密钥与读模式 → 部署 → 用真实已核验候选做发布、检索、撤回及失效验收。

本次只开发代码与隔离回归，不操作生产迁移、生产权限、自动任务或数据库读源切换。认证的已上线证据另见 [2026-09-13 认证验收](production-evidence/2026-09-13-admin-auth.md)。
