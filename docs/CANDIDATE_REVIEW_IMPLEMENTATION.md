# 候选审核到发布实施设计

状态：开发中 · 2026-09-21。范围是代码、隔离测试及 PR；生产启用另行批准。

## 目标与边界

[事实] 现有候选材料页只读，已有底层不可变版本、核验、组装与发布服务，但生成结果不是正式候选，管理员会话不是核验或发布许可。

目标：任务内保存审核与补全、幂等转换、消费可信核验、显式发布/撤回、形成可执行验收清单。不自动调用 AI，不把上传的私有引用自动复制成公开证据，不自动批准生产权限或切换公开数据源。

## 方案与取舍

| 方案                               | 一致性和审计                           | 安全/迁移代价                            |
| ---------------------------------- | -------------------------------------- | ---------------------------------------- |
| 在生成 JSON 内覆盖审核状态         | 无独立审核修订；会改写历史结果         | 复用生成写权限，但混淆模型输出和人工决策 |
| 独立追加审核记录及转换回执（采用） | 固定原材料指纹、审核修订、CAS 和幂等键 | 新私表与专用角色，生产必须独立审批       |

## 数据流及信任边界

生成任务 → 原文/候选复检 → 审核修订 → 正式私有版本 → 独立签名核验报告 → 已核验新版本 → 显式受控发布。

- 浏览器只提交编辑内容和动作，不提交 owner、发布租约或可信核验布尔值。
- 审核记录追加写，绑定任务、原始序号和材料哈希；改动必须新修订，旧请求不得覆盖新决定。
- 转换仅引用已登记核验的公开 Evidence 和稳定实体；事件键去重，禁止静默合并不相同事件。
- 核验签名使用 Ed25519；服务端仅保存可信核验方公钥及固定 verifier ID，私钥不进入网站。签名报告绑定审核修订、材料、正式快照和六项核验结论，含逐项理由和短时接收窗口。签名验证只证明来源，不证明事实本身；独立核验方必须实际完成来源许可、事实、人物、组织、反证检查。
- 已有核验记录、组装及发布分别提交，不能把同事务新行伪装成已封存材料。
- 发布复用 Publisher 的完整权限、数据库开关、任务授权、租约、修订、permit/outbox 与依赖失效检查。撤回不依赖公开读模式。

## 风险、自评与反对意见

最强反对意见：多角色与签名核验增加操作成本，简单管理员“通过”更快。回应：当前产品明确要求可信事实核验；合并权限会使任何会话或模型输出直接成为公开许可。当前选择安全分离，不能以页面按钮齐全冒充可信核验服务已运营。

主要失败模式：旧审核覆盖新审核（CAS/材料绑定）；重复请求重复版本或发布（固定键/唯一约束）；错误事实被可信签名背书（必须独立核验，签名不代替事实核查）；提交结果未知（保留原键查询，不自动重试）；生产仍旧数据源（服务端禁止发布）。

自评：正确性、安全、可运维性均需要新数据库集成及端到端测试通过；生产启用有条件通过，凭据、核验方与真实公开证据未配置不能宣称完成。
