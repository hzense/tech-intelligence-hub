# 信号发布与事后管理

## 自动发布增量（2026-10-21，本地验证通过，尚未生产启用）

在显式开启自动发布后，新生成且完整的公开网页候选可直接发布。无需逐条人工确认，只有缺项、身份冲突或来源读取异常进入待处理。旧任务不补发，上传文件和受保护来源不自动公开。详见 [自动发布策略](AI_SIGNAL_GENERATION.md#自动检查后发布与事后管理2026-10-21本地验证通过默认关闭)。

原确认页面现在作为“信号管理”：标题和摘要可以修订（80／500 字），发布信息仍可调整，已发布记录显示“保存修改”及“撤回发布”。保存新版本后，公开读取与搜索、雷达、资源关联使用最新有效版本。撤回保留审计、不会删除原始候选；未保存编辑不会影响要撤回的已发布版本。

数据库追加 `editorial_signal_revisions.publication_basis`，区分 `automatic_checks` 与 `manual_confirmation`；统一版本表记录相同依据。自动路径只能写首次发布，不能修改既有人工记录，HTTP 调用方不能自行指定自动身份。重试仅处理发布回执，不重新收费生成。

生产启用顺序：迁移 0032 → 审核并执行最小 ACL 升级 → 验证编辑／撤回及公开读取 → 开启独立自动发布总开关，并在自动采集配置中明确选择自动发布。回退时关闭总开关，已发布内容仍可人工编辑撤回。生产步骤须按受保护维护流程另行审批；下面的旧阶段说明不代表本次已上线。本地真实 AI 在现有迁移／角色初始化完成后可直接在采集配置页保存发布方式；旧配置默认人工审核，改动仅影响新任务，详见[本地配置](LOCAL.md#本地自动发布配置默认人工审核)。

## 使用方式

从 AI 生成任务打开候选后，核对标题、摘要以及四项信息：

1. 事件日期（不是采集日期）。
2. 至少一个组织名称。
3. 至少一个人物姓名。
4. 至少一个启用领域，可输入名称检索并选择已有领域，最多五项。

系统尽量沿用原候选、已有补全及补证结果；缺项直接手填。四项齐全后点击一次“确认发布”即公开，不再要求六项声明、实体登记、独立签名核验和受限发布组装。未补齐可“保存补充”。已发布可以确认更新或撤回。

发布依据明确为“管理员确认”，不标记为独立事实核验通过；不编造组织类型、人物身份、置信度、热度或趋势分数。人物／组织此阶段是人工确认的名称，不冒充已核验实体关系。原始候选与证据折叠辅助查看，不会自动公开原文件、原文快照、导入地址或私有任务编号。标题和摘要仍取原候选，不在这次表单中编辑。

## 保存与公开读取

- `editorial_signal_revisions` 保存追加式 draft / publish / withdraw 修订，原 AI 结果和账本不变。
- `editorial_public_signals` 仅投影每个候选最新修订中已发布的记录，不暴露 owner、原任务编号、证据和审计元数据。
- 正式信号列表、详情和搜索叠加人工发布条目；撤回直接从实时视图消失，旧搜索索引不能让内容重新出现。
- 日期和名称格式、至少一个人物／组织／领域、实时领域目录、管理员归属、材料指纹、确认动作、请求幂等和修订并发控制均由服务端检查。
- 网络超时不等于保存失败；页面保留原请求，先核对状态或重试原编号。重复点击不会追加重复修订。
- 已发布候选必须先撤回再删除原生成任务，避免失去撤回入口。

### 数据库权限边界

pgvector 例外使用仓库固定的 0.8.6 函数清单（`editorial-vector-manifest.mjs`）：核对 118 项函数的名称、参数／返回类型、语言、库与实现符号及执行属性，同时限制版本、所有权、安全模式和 ACL。四项聚合另核对 `pg_aggregate` 定义与支持函数身份；即便支持函数撤销了 PUBLIC EXECUTE，也核对其所有权、安全属性与实现。清单来自隔离 PostgreSQL 18 的全新安装，不从生产库动态学习；等量替换扩展成员也会拒绝。升级扩展须重新审核清单。

专用角色校验覆盖应用数据库精确表／列 ACL、成员资格、对象所有权、参数 ACL，以及其他数据库的直接授权和非保留库的有效访问。它沿用项目现有的 Neon 平台信任边界：仅允许 `cloud_admin` 所有的 `postgres`／`template1` 满足精确默认数据库 ACL 形态时保留平台访问；这不是对整个 PostgreSQL 实例的绝对隔离保证。

应用不得在这些提供商保留库中存放业务数据或创建可供 PUBLIC 访问的业务对象。当前连接无法跨库检查保留库内部的对象 ACL，因此不能将此校验报告为保留库对象审计已通过。若平台保留库承载了自定义对象，必须先另行审计并消除暴露，不能直接启用本功能。本批不修改提供商保留库或其系统 ACL。
