# 来源采集与专题洞察任务

本功能是 Signal-first 重构的后台阶段。代码交付不等于生产已启用；默认不得运行定时任务、迁移生产库或调用模型。

## 操作入口

- 管理员的“自动采集”只需选择已就绪的分阶段模型配置，不提供领域选择，也不要求填写网址。新建或重新保存的联网采集配置使用空 `topicIds`，执行器从 `data/taxonomy/taxonomy.yaml` 读取全部一级科技领域作为检索范围（不是仅有内容页或已有信号的领域）；可选关键词或人物／组织（最多 10 个）。默认检索近 2 天、最多读取 5 篇原文；可选 1／2／7／30 天、1–8 篇原文。新配置默认关闭定时执行，频率默认每日，可改为手动或每周。有限检索次数不保证每次覆盖每个领域。旧配置的领域限制在管理员明确重新保存前保留，已有运行快照不变；页面会提示保存后的范围变化。专题洞察仍保留专题选择。
- 联网发现使用 Profile 的 `analyze` 模型与连接，使用独立的服务器检索规则，不套用原分析阶段的报告提示词；原文提取仍使用 `extract`。目前联网发现要求分析模型使用 `https://openrouter.ai/api/v1`，并在运行时通过模型目录确认支持工具调用。保存配置不调用模型、不立即启动计划。
- 一次采集先让 AI 根据领域和关键词调用真实搜索工具，选择有引用且在日期窗口内的来源，然后复用受保护的原文获取／解析流程，为成功资料创建私有生成任务；每篇资料继续遵守现有每次最多 5 条候选、标题 80 字、摘要 500 字及证据校验规则。搜索摘要不能冒充原文，不会自动审核或公开信号。
- “专题洞察”配置专题及已就绪的分阶段模型 Profile（最多 5 个专题）。任务只读取近 30 天的当前公开信号，至少两条；冻结输入版本，生成附信号引用的私有报告。管理员阅读后点击确认公开，亦可撤回。
- 定时 Cron 每日 01:00 UTC 检查到期配置；每周配置在周一 UTC 执行。保存或编辑配置不立即运行。配置/任务编号与日期槽保证重复请求不再次创建同批次。
- 结果未知的任务必须先核对账本和原任务；不会为追求成功自动重做付费调用。专题依据的任一信号撤回或内容变化后，旧报告停止公开。
- 配置列表提供“删除配置”：确认后停止未来调度并隐藏配置。历史任务、结果、费用以及已公开的专题报告不会随之删除或撤回。软删除不能通过页面恢复；如确需重新建计划，需显式新建配置。

## 安全边界

- 配置存储与执行独立：配置列表和未启用配置的保存只使用 `HZENSE_AUTOMATION_DATABASE_URL`，仍核验专用角色、目标、TLS、Schema 与最小列权限，不要求 `HZENSE_AUTOMATION_ENABLED=1`、执行预算或导入／生成开关。保存仍验证所选 Profile 和连接是否符合要求，不调用模型。关键词可留空，也可填写最多 10 个关注词。
- `HZENSE_AUTOMATION_ENABLED` 仅控制运行与开启计划；运行还须有合法预算及对应依赖服务。手动启动、Cron 派发和 Worker 数据库入口保留执行门禁，不能通过直接请求 API 绕过页面禁用。关闭执行时仍能查看配置／任务、保存未启用配置或关闭旧计划；仍处于启用状态的旧配置须先取消“允许定时执行”再保存，不静默改变已有授权。
- 页面分别显示“存储未就绪”“存储就绪但执行未就绪”。开放保存不会自动运行；开启定时计划是独立的显式选择，首次运行仍是下一个 UTC 日期槽。专题公开读取仍由独立 Reader 开关控制。
- 发现采用 OpenRouter `openrouter:web_search` 服务端工具，固定 Exa fast 引擎，不启用原生搜索回退；每次最多 3 次搜索、累计 8 个搜索结果、每个结果摘要最多 1,000 字符，模型输出最多 2,048 tokens。调用前经模型目录只读兼容性检查，实际检索计数缺失／为零时不会将模型记忆当作搜索结果。
- 仅接受供应商 `url_citation` 中可追溯的公开地址。移除已知跟踪参数后与当前公开 Signal（含 Seed）、同一管理员已派发候选的采集记录去重；同批网址去重，跨网址相同解析内容由既有导入／生成检查阻断。模型被要求合并同一事件的转载，但语义去重不是确定性保证，仍须人工审阅。URL 检查、DNS/IP 防护、隔离解析、临时原件清理及原文证据要求不变。
- 日期窗口依据发现结果所报的资料发布日期作初筛，不等于原文事件日期已核实；生成阶段仍须从原文识别事件日期，人工审核须区分旧事件重发和真正新进展。没有合格新来源时记录 `no_new_sources`，不创建空导入批次或编造候选。当前不保证全网覆盖、付费墙可读、RSS 订阅或 OCR。
- 管理接口要求已登录管理员、可信同源请求与严格参数；任务状态、费用和结果在私有库。公开页面仅使用专用只读视图读取已确认且仍有效的专题报告。
- 采集/生成、专题模型和公开读取分别由开关控制。模型结果不能直接发布 Signal；专题报告也要管理员单独确认。
- 联网发现与专题 AI 共用自动任务预算账本，claim 时串行检查并预留；发现调用另有一次性持久化阶段锁，重复 Workflow 不会再次付费调用。费用优先使用 API `usage.cost`，缺失时采用保守模型用量估计加检索费估计；输出校验失败也保留已取得的费用，超时或供应商结果不明确时保留预留额，不自动重试。当前检索费用估计使用每次 0.007 美元（2026-09-30 官方文档），不是供应商硬性限价。
- `HZENSE_AUTOMATION_*` 只覆盖联网发现／专题模型费用；后续导入和候选生成分别使用原有独立预算，不是一个合并总额度。配置数值以微美元为单位，正整数且单任务预留不超过批次，批次不超过 UTC 日上限。需按所选模型费率设置足够预留；模型费用配置过低会低估用量，供应商账户也应设置消费上限。

## 旧配置与任务结果

- 新表单不再提供固定网址输入。旧的已保存配置和运行快照保留原意，继续按原方式执行；不会在升级代码后静默增加联网费用。点击编辑时显示转换说明，清空旧网址并关闭定时开关；确认新配置并保存后才转换为联网发现，无需额外指定领域。手动指定网址继续使用“导入已解析资料”。
- 运行列表展示实际检索次数、选中来源、重复／不合格条目、原文链接、导入批次与候选任务链接。`candidate_tasks_queued` 只表示已派发，不代表生成成功或发布；每个候选任务单独核对。发生不确定错误时保留已登记批次和候选编号。
- 配置及发现回执使用 `0026` 已设计的私有 JSON 字段；本次删除另需 `0027` 的软删除列与两项最小列权限，不新增物理表。尚未完成 `0026` 生产准备的环境仍需先走以下门禁；下述冻结流程不能捎带执行 `0027`。

## 兼容性与验证边界

OpenRouter 服务端搜索工具仍为 Beta，协议或模型支持可能变化；实现依据 [Web Search 官方文档](https://openrouter.ai/docs/guides/features/server-tools/web-search)（核对日期 2026-09-30）。未确认实际检索、模型不支持工具、返回无引用或原文读取失败时停在私有任务，不降级成凭记忆生成。首版复用现有连接，不新增搜索供应商密钥；后续可增加独立搜索适配器或 RSS 补充发现。

本批为本地实现。合成测试不证明生产工具兼容性和实际覆盖率；生产需要单独授权一次有界付费验收，之后再启用计划。不得将代码通过测试写成已经开始自动采集。

本地验证（2026-09-30）：Web 752 项通过／14 项环境相关跳过，数据库包 2,360 项通过／688 项环境相关跳过；另独立启用后台浏览器测试 1 项通过，使用本机新建隔离 PostgreSQL 18.4 集群运行自动任务最小权限与发现账本测试 2 项通过（完成后停止测试集群）。构建、Web 类型检查、Web／数据库 lint 通过。覆盖无网址保存、旧配置显式转换、工具次数、来源引用、日期／网址过滤、费用回执、重复调用锁、无新来源、部分原文失败及派发不确定回执；未访问生产数据库或调用真实模型。

## 生产启用前门禁

1. 对照 main 已合并代码与 CI，保留新备份并独立确认预期生产目标；恢复能力如未演练，要明确接受该风险。采用下述组合入口时，实时只读 preflight 在同一次批准后执行，无需先另行申请预检审批。
2. 审批 0026 迁移并完成独立只读结构核验。2026-10-02 新增的 `migrate-and-verify` 入口在一个受保护 job 内依次执行 runner prepare（preflight → ACL 双采集及安全落盘）→ upload-artifact 远端归档成功 → runner apply（migrate → 独立 verify），只需一次 **Review deployments**，不增加独立 preflight 或阶段审批。任一步失败即停止，附件上传失败不执行 DDL；prepare 仅报告 `status=prepared`，最终 apply 完成才是 `status=succeeded`。本批为本地修改，待 PR／合并／main CI 后才可在线使用。原有独立入口保留，不能复用旧审批。详见[0026 单次审批维护](ONLINE_MAINTENANCE.md#0026-单次审批维护)。
   - 恢复尚未演练时，仅可在用户明确接受本次风险后使用 `accept-unverified-automation-storage`，风险范围为 `automation-storage-production-launch`。新组合入口只支持这一范围，冻结完整 0000–0026 清单，只接受单个待迁移 0026。批准前可用固定迁移清单、独立确认的预期生产目标与新备份，通过 `automationTargetBinding`／`automationMigrationPlan` 纯计算绑定指纹，不连接生产；同目标／备份／清单的已有脱敏预检仅供辅助复核，不必为了取得同一计划再审批预检。不得从待检连接串反推预期目标；获准组合 run 第一阶段会读取实时连接和待迁移状态，与明确批准的计划一致才继续。审批仍绑定 SHA、run／attempt、过期时间、备份、目标、清单和计划，并确认备份期限、维护冻结、恢复未验证风险及 main／CI 门禁。
   - 组合审批必须使用 `aclEvidenceMode: "capture-in-run"`，明确 `publicArchiveApproved: true` 和当前归档仓库；不填写 `aclFingerprint`，由同一 run 的真实双采集产生。真实证据安全落盘成功后才设置固定附件就绪 output flag，上传固定脱敏证据文件成功后才允许 apply。apply 读取同一 run／SHA／attempt 及原审批摘要绑定的证据，并在迁移锁内再次比对 ACL。迁移前已完成远端归档，后续迁移或核验失败也保留附件。阶段由工作流固定，不增添操作者审批字段。旧范围及未来迁移不得混用。失败不自动重试或回滚；迁移阶段开始后失败可能已提交，须先只读核验，再为新 run 重新批准。
   - 新角色脚本位于 db/roles/create_automation_roles.sql 和 db/roles/configure_automation_roles.sql，需在迁移核验后按其限制分别执行和核对最小 ACL，不借用旧角色授权。角色授权、凭据、Vercel 配置／部署、采集开关、定时计划、AI 调用与专题公开读取均不在这次组合维护范围内。
3. 先在 Production Secret 配置 `HZENSE_AUTOMATION_DATABASE_URL` 并重新部署；执行开关保持关闭，核验配置保存及刷新读回、不生成任务。需要公开专题时再配置 `HZENSE_INSIGHT_READER_DATABASE_URL`。执行前另行设置 HZENSE_AUTOMATION_BATCH_LIMIT_MICROUSD、HZENSE_AUTOMATION_DAILY_LIMIT_MICROUSD、HZENSE_AUTOMATION_RESERVE_MICROUSD，确认 Cron Secret 配置和模型/导入既有门禁，再单独启用 HZENSE_AUTOMATION_ENABLED。公开专题另需 HZENSE_TOPIC_INSIGHTS_ENABLED。
4. 先只读检查管理页和公开页，再做一次可追溯的“不选领域、不填网址”手动采集及专题验收：核对默认科技范围、实际检索、原文、去重、候选入库、费用、引用、人工确认、撤回与依赖信号变更后的下架。专题洞察仍需选择分析专题。最后再启用计划频率。

不在文档、日志或 PR 中记录密码、完整连接串、原件或私有候选正文。
