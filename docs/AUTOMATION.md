# 来源采集与专题洞察任务

本功能是 Signal-first 重构的后台阶段。代码交付不等于生产已启用；默认不得运行定时任务、迁移生产库或调用模型。

## 操作入口

- 管理员的“自动采集”配置固定公开文章链接（每项最多 8 个），可手动触发，或选择每日／每周 UTC 计划。一次运行先复用导入解析，再为成功资料创建私有信号生成任务。生成任务可能另行产生费用，但不会自动审核或公开信号。
- “专题洞察”配置专题及已就绪的分阶段模型 Profile（最多 5 个专题）。任务只读取近 30 天的当前公开信号，至少两条；冻结输入版本，生成附信号引用的私有报告。管理员阅读后点击确认公开，亦可撤回。
- 定时 Cron 每日 01:00 UTC 检查到期配置；每周配置在周一 UTC 执行。保存或编辑配置不立即运行。配置/任务编号与日期槽保证重复请求不再次创建同批次。
- 结果未知的任务必须先核对账本和原任务；不会为追求成功自动重做付费调用。专题依据的任一信号撤回或内容变化后，旧报告停止公开。

## 安全边界

- 来源链接沿用导入的 URL 检查、隔离解析和预算。当前没有 RSS 发现、全网覆盖保证或 OCR。
- 管理接口要求已登录管理员、可信同源请求与严格参数；任务状态、费用和结果在私有库。公开页面仅使用专用只读视图读取已确认且仍有效的专题报告。
- 采集/生成、专题模型和公开读取分别由开关控制。模型结果不能直接发布 Signal；专题报告也要管理员单独确认。
- 专题 AI 每次预留预算并单次调用；供应商结果不明确时保守保留预留额，不自动重试。配置的预算数值以微美元为单位，正整数且单任务预留不超过批次，批次不超过 UTC 日上限。

## 生产启用前门禁

1. 对照 main 已合并代码与 CI，保留新备份并执行只读 preflight；恢复能力如未演练，要明确接受该风险。
2. 单独审批 0026 迁移，迁移后运行完整只读结构核验。新角色脚本位于 db/roles/create_automation_roles.sql 和 db/roles/configure_automation_roles.sql，需按其限制分别执行和核对最小 ACL，不借用旧角色授权。
3. 在 Production Secret 中配置两个专用数据库连接；设置 HZENSE_AUTOMATION_BATCH_LIMIT_MICROUSD、HZENSE_AUTOMATION_DAILY_LIMIT_MICROUSD、HZENSE_AUTOMATION_RESERVE_MICROUSD。确认 Cron Secret 配置和模型/导入既有门禁，再单独启用 HZENSE_AUTOMATION_ENABLED。公开专题另需 HZENSE_INSIGHT_READER_DATABASE_URL 与 HZENSE_TOPIC_INSIGHTS_ENABLED。
4. 先只读检查管理页和公开页，再做一条可追溯的手动来源与专题任务验收：核对入库、费用、引用、人工确认、撤回与依赖信号变更后的下架。最后再启用计划频率。

不在文档、日志或 PR 中记录密码、完整连接串、原件或私有候选正文。
