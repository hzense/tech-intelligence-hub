# 本地开发与验证

目标是**线上服务不可用时仍能在本地开发、运行测试，提交评审后用同一份代码部署线上**，不是另建一套只读离线产品。

当前提供两种入口：`local:browse` 仅浏览仓库快照；`local:dev` 使用同一套 Next 管理后台与业务代码，接入本机 PostgreSQL、免令牌本地身份、私有临时文件、Docker 解析和本地任务。**默认仍为不调用供应商的模拟 AI 模式**；显式运行 `pnpm local:dev --ai=real` 才使用本地保存的连接与模型执行真实 AI，并支持手动启动一次自动采集。真实调用需要联网，可能产生供应商费用并外发选中的解析资料；它不是离线功能。定时调度、专题自动执行和 AI 补全仍未本地化。

此前后台适配与模拟生成 HTTP 闭环已验收；生成工作台及候选详情也已通过浏览器检查。该次验收使用此前的一次性令牌登录，随后改为仅限可信本机的免令牌进入，并另行完成后台直达、同源读取及错误 Host／Origin 拒绝的实际复验，没有重复生成或发布。**新增真实 AI 模式的验收须单独记录**；下文既有数据库、接口和浏览器检查不能作为真实供应商模型已通过的证明。

## 两个环境，一套业务代码

| 边界             | 本地开发／验证                                                            | 线上生产                                    |
| ---------------- | ------------------------------------------------------------------------- | ------------------------------------------- |
| 源码、契约、迁移 | 当前 Git 工作区                                                           | 经评审合并的同一提交                        |
| 数据             | 仓库快照、独立开发库、合成测试资料                                        | Neon 中的正式数据                           |
| 认证、文件、任务 | 免令牌本地身份、本机私有文件、Docker 解析、本地 Workflow；访问边界已复验  | 既有 Google、Blob、Sandbox、Workflow 等实现 |
| AI               | 默认固定模拟 Profile；显式 `--ai=real` 使用本地密钥、配置与预算调用供应商 | 独立凭据、预算、开关及实际调用              |
| 发布             | 测试不得影响线上内容                                                      | 生产依赖就绪后人工确认发布                  |

本地数据、密钥和生产数据不自动双向同步。代码可以离线修改和提交到本地 Git；推送 GitHub、拉取新依赖／镜像、远端 CI、线上部署及真实 AI 调用仍需相应网络与服务可用。

## 公开页面预览

- 雷达、信号列表与详情、洞察、资源和搜索。
- 数据来自仓库内的 `data/seed/`、`data/taxonomy/` 和 `content/`。
- 当前 Seed 包含 **110 条信号**；它是仓库快照，**不是生产数据库备份**，不包含仅在生产库中生成、审核或新发布的记录。
- 搜索使用本地进程内索引，不使用数据库 FTS。

启动不需要数据库、`.env` 或 API Key，也不会连接 Neon。安装依赖需要联网；页面中的互联网图片和来源链接仍需联网，不能将本版本理解为完整离线镜像。

## 安装与启动公开页面

需要 **Node.js 24** 和 **pnpm 11.21.0**。macOS 尚未安装 Node 时，可从 [Node.js 官方下载页](https://nodejs.org/en/download)选择 24.x 的 macOS 安装包；安装后重新打开终端。

```bash
node --version
npm install --global pnpm@11.21.0
pnpm --version
```

在仓库根目录执行：

```bash
pnpm install --frozen-lockfile
pnpm local:check
pnpm local:browse
```

`local:check` 检查本地运行条件，不启动网站；`local:browse` 启动支持热更新的开发服务器，`local` 保留为兼容入口。浏览器打开 **http://127.0.0.1:3000**，启动终端需保持运行。停止时在该终端按 **Ctrl+C**。

若 3000 端口被占用，可运行 `pnpm local --port=3001`，然后访问 http://127.0.0.1:3001 。服务只监听本机回环地址，不对局域网开放。

这只是本机服务，不会部署或恢复 `hzense.com`，也不会修改生产配置、迁移数据库或调用 AI。

本模式没有数据库连接，因此 `/api/health/database` 返回 `503 unavailable` 是预期行为，不代表公开浏览页面启动失败；应通过首页、信号详情和搜索来验收。管理接口仍要求身份验证，不开放匿名写入。

## 遇到环境配置冲突

本地启动器会拒绝可能被 Next.js 自动加载的环境文件，避免 `.env`、`.env.local` 等文件把生产数据库连接或云服务密钥带入本地进程。仓库的 `.env.example` 只是说明文件，不需要复制。

如果检查指出环境文件冲突，**不要为了启动而删除现有配置**。推荐另建一个没有运行时环境文件的工作目录：

```bash
git worktree add --detach ../tech-intelligence-hub-local HEAD
cd ../tech-intelligence-hub-local
pnpm install --frozen-lockfile
pnpm local:check
pnpm local:browse
```

新 worktree 使用当前已提交版本，不包含原目录尚未提交的修改。请确认其中已经包含本地启动功能。也不要把 Vercel 导出的生产环境文件复制进来。

## 日常代码验证

```bash
pnpm local:verify
# 先停止 Next 开发服务器，再验证生产构建：
pnpm local:verify --build
```

此入口按顺序执行工作流契约、内容、Seed、lint、类型和默认测试，某一步失败即停止；`--build` 额外执行工作区生产构建。它使用显式环境白名单，不继承生产数据库、OAuth、Vercel、GitHub、AI 密钥，也拒绝 Next.js 自动读取的开发／生产／测试环境文件。

默认测试会跳过需要 PostgreSQL、浏览器或额外 Python 依赖的测试；通过不等于所有后台流程已端到端验证。入口不自动安装依赖，不执行联网安全审计、浏览器测试、付费 AI 或部署。构建前检测到 Next 开发锁时会停止，避免覆盖正在使用的构建产物。

## 本地 PostgreSQL 底座

需要可运行的 Docker Engine 与提供 `docker compose` 命令的 Compose 插件。Mac 可安装并启动 [Docker Desktop](https://docs.docker.com/desktop/setup/install/mac-install/)；Apple Silicon 使用相应安装包。系统权限与许可步骤由操作者确认。

```bash
pnpm local:db:doctor
pnpm local:db:up
pnpm local:db:init
pnpm local:db:verify
pnpm local:db:test
# 停止开发容器，保留数据卷：
pnpm local:db:stop
```

- 镜像与 CI 一致：PostgreSQL 18、pgvector 0.8.6，固定镜像摘要；首次拉取需要联网。
- 开发实例仅绑定 `127.0.0.1:55432`，使用持久数据卷；测试实例为另一独立集群，使用 `127.0.0.1:55433`。测试会操作集群角色，不能仅在开发实例内新建一个测试库。
- 命令不接受生产连接串覆盖，不使用远程 Docker context，不拉取生产环境文件。私有本地配置保存在 Git 忽略的 `.hzense-local/`，不要提交或复制到 Vercel。
- `init` 在专用开发集群创建 `hzense_local`，执行仓库迁移和完整结构校验，将仓库 Seed 归档并回填到统一 Signal 结构、同步 Topic。原有 owner、runtime、editorial reader／writer 之外，后台增量追加 AI 配置、导入、生成、候选审核、只读工作台和自动任务配置六个最小权限角色；复用仓库已审核的角色 SQL／列权限矩阵和精确权限核验，不给应用 owner 权限。
- 已初始化的库再次运行 `init` 不会重写已就绪的 110 条 Seed 或重置原有密码。凭据文件当前为 v3：从 v2 升级只追加自动任务配置角色密码，原密码及 AI 加密密钥保留；从 v1 升级还会补齐此前后台角色及本地加密密钥。密钥持续保留，用于读取已保存的本地连接配置。
- `verify` 检查本地数据库身份、结构契约、精确角色权限、角色真实登录及统一公开视图。命令实现与真实执行验收是两回事，必须以实际输出为准。
- `test` 使用独立临时集群运行现有真实 PostgreSQL 迁移／角色／事务测试；仅清理本次新建且核验通过的测试容器，遇到已有或身份不明的容器会停止。`stop` 不删除开发数据卷，无全局 `docker prune` 或生产清理行为。
- 尚未安装／启动 Docker 时，`doctor` 会失败并说明前置条件；此时不能宣称数据库实际初始化或集成验收已完成。

## 启动本地管理后台

先完成 PostgreSQL 准备，并构建本地隔离解析镜像。首次构建需要联网获取固定基础镜像和 Python 依赖；镜像存在后，文档解析容器本身禁用网络。

```bash
pnpm local:db:doctor
pnpm local:db:up
pnpm local:db:init
docker build --tag hzense-local-import-parser:1 docker/local-import-parser
pnpm local:dev:check
pnpm local:dev
```

`local:dev:check` 检查本机数据库身份、结构、权限和开发环境，不启动网站，也不等同于解析镜像或浏览器整链验收。`local:dev` 使用本机数据库读取公开 Signal；`local:browse` 仍为独立的无数据库快照入口。两者不能同时占用同一个端口；需要换端口时使用 `pnpm local:dev --port=3001`。

打开 **http://127.0.0.1:3000/admin** 即可直接进入，**无需令牌、登录表单或 Google 登录**。启动器不再签发登录令牌、会话密钥或登录 Cookie；旧版生成的私有令牌文件不再被读取。严格本地环境校验通过时才使用固定的 `local:developer`／`developer@localhost` 开发身份，生产 Google 身份验证保持不变。

此模式信任**所有能够访问本机 `127.0.0.1` 的进程和操作系统用户**，不是只有当前 macOS 账号可以访问。入口只监听回环地址，并核对 Host／Origin、防止跨站请求；这些限制不代替本机用户隔离。只在可信个人电脑使用，不要改为 `0.0.0.0`，不要通过代理、隧道、端口转发或局域网共享后台。无需使用时按 **Ctrl+C** 停止开发服务，即结束后台可访问性；数据库内容仍保留。

### 本地数据与原件

- 初始数据仅为仓库 110 条 Seed、Topic 投影和之后在本地创建的测试记录，不导入生产私有配置、任务或候选。
- 导入原件临时写入 `.hzense-local/import-originals/`，目录／文件采用私有权限；文件名不会直接作为宿主机路径。处理成功或失败后沿现有清理流程删除原件，不作七天原件归档；中断或清理失败应核对任务，不能把“计划删除”当成已删除。
- 解析使用非 root、无网络、只读根文件系统、有限内存／CPU 的 Docker 容器，不在宿主机执行文档内容。解析结果与任务记录进入本地 PostgreSQL；原件删除不删除解析结果、候选或审计记录。
- Workflow 的本地状态保存在 `.hzense-local/workflow/`。数据库使用独立持久数据卷；停止服务或容器不会清空数据。
- AI 连接与模型配置使用本地专用角色和加密密钥。默认 `mock` 模式可创建、读取和修订未验证草稿，生成页面只提供独立、明显标记的模拟 Profile；`real` 模式才允许启用连接、读取模型列表、执行能力测试并使用通过就绪校验的 Profile。配置已保存不等于模型可用。
- 公开搜索继续使用进程内索引，并读取本地公开 Signal；本轮不将其描述为本地数据库 FTS 验收。

### 本地真实 AI 配置与执行（2026-10-20）

此模式与默认模拟模式共用本地数据库，**不读取或复制生产 AI Key、Profile 或任务**。启用方法如下：

1. 完成前述数据库初始化；停止已运行的开发服务器后，执行 `pnpm local:dev --ai=real`。只刷新浏览器不会改变启动模式；检查页面标记明确显示真实 AI，而不是模拟结果。
2. 在 `/admin/ai` 创建或修订本地连接，填入自己的供应商 API Key，核对接口、预算和单价后启用。密钥仅存入本地数据库的加密凭据，本地根密钥保存在被 Git 忽略的 `.hzense-local/`。不要把 Key 写进文档、Git 或终端命令，也不要拉取生产环境变量。
3. 读取该连接的模型列表，选择模型并显式执行基础连接和结构化输出测试；如果配置要求工具能力，还需对应测试。模型列表读取不是能力证明，测试可能产生费用。
4. 在 `/admin/ai/profiles` 为三个阶段选择当前连接与模型，保存通过就绪检查的配置。既有草稿不会因换到 `real` 模式自动就绪；连接启用、密钥、修订和必要能力证明仍逐项校验。端点、密钥或其他连接配置改变后，需要按当前修订重新测试和保存。
5. 导入并解析资料，在 `/admin/signal-generation` 选择该资料和就绪配置。先检查资料，再明确同意将内容发送给所选供应商并产生费用，创建并执行任务。实际生成由本机 Workflow 执行，使用本地保存的配置、任务和预算，不派发生产任务或云端 Sandbox。
6. 查看候选与证据，人工核对后按本地发布流程继续。生成本身不自动发布，也不把本地内容同步到生产。

真实生成沿用现有结构、原文引用、幂等、租约和预算门禁；当前本地生成上限为**单批 5 美元、UTC 每日 10 美元**。连接能力测试还有自己的预算记录，不包括在生成页的当日生成费用合计内；供应商费用回传缺失时保留估算，页面记账不等于供应商最终账单，也不能当成账户总消费的绝对封顶。

本地允许的接口域名为 `openrouter.ai`、`ai-gateway.vercel.sh`；HTTPS、公网 DNS 校验、禁用重定向和凭据绑定规则与生产执行保持一致，不因本地模式开放任意地址。配置页面或启动器不自动发起付费测试或模型生成。

模拟与真实任务不能跨模式执行。切换前先检查在途任务，勿用换模式、换请求编号或重复提交来绕过未知结果；历史记录继续保留，需回到原模式核对任务。默认模拟验收脚本 `local:dev:smoke` 只用于 `mock` 模式，不用它验收真实付费调用。

切回模拟模式时停止服务器，再运行 `pnpm local:dev`（或显式 `pnpm local:dev --ai=mock`）。本地已经保存的连接和配置不会删除，但模拟模式不执行供应商请求。无论哪种模式，本地后台均只信任本机回环访问；真实模式中的 Key 和可执行预算进一步要求不要共享电脑后台、代理或隧道。

本段描述新增模式的使用契约，不代表真实供应商调用已经验收。合成响应测试只证明代码路径，真实 Key、模型兼容性、费用及内容质量须由操作者在明确外发和费用授权后单独验证。

### 本地自动采集（2026-10-20）

显式 `pnpm local:dev --ai=real` 支持在 `/admin/sources` 点击“立即运行”后自动完成联网发现、原文导入解析和私有候选生成。修改启动器后需停止并重新启动服务，仅刷新页面不能使新开关和预算生效。

1. 先按上节配置真实 AI。联网发现使用 `analyze` 阶段的 OpenRouter 连接，运行时核对模型同时支持工具调用和结构化输出；后续生成沿用同一 Profile 的生成配置。Profile 必须为当前修订且通过就绪检查，已保存的草稿不等于可执行。
2. 在自动采集页选择配置并保存。关键词可不填，默认覆盖 Taxonomy 中的一级科技领域；保存不会调用 AI。本地仅支持手动启动，定时开关禁用，保存强制使用 `enabled=false` 和 `frequency=manual`。
3. 点击“立即运行”并确认资料外发与费用后，本机 Workflow 调用联网搜索、校验来源，再在本机获取公开网页，以禁网 Docker 解析。原件按导入清理流程删除，解析结果和任务保存在本地数据库。
4. 成功解析的资料创建本地私有生成任务，派发到本地生成 Workflow，不调用 GitHub 执行器或云端 Sandbox；候选仍需人工审核，采集不会自动公开内容。

采集预算为**每次 5 美元、UTC 每日 10 美元**，与生成的**每批 5 美元、UTC 每日 10 美元**分别记账；能力测试也另计。采集排队执行后预留 5 美元，已知结果按现有供应商回执／估算规则记账。运行中或费用未知继续保守占用预留；若检索已取得一致的供应商费用回执、任务已结束且无租约，仅后续导入／派发结果未知，则按检索回执金额占用预算，不因后续失败继续占满 5 美元。回执缺失、估算或金额不一致仍保留预留。这不是将每次实际费用固定为 5 美元，也不是供应商账户总消费的硬封顶。

任务列表保留来源诊断和候选任务链接。采集任务完成只表示其子任务已登记／派发，不能据此断言每条候选都已生成；请查看相应生成任务的实际状态。结果未知时保留原编号人工核对，不自动重复付费请求。

本地原件存储与导入接口共用 `importUuid` 记录编号契约。自动采集的稳定哈希编号并不保证 RFC UUID 版本／变体位，不能用仅接受标准随机 UUID 的路径规则拒绝它；路径仍严格限于 `imports/<batch>/<item>`，保留小写十六进制、长度、目录权限、文件哈希及防符号链接校验。修复此校验不会改写旧编号或自动恢复已经结束为 `unknown` 的任务；需单独核对原批次，不能通过重新搜索掩盖原任务或重复付费。

模拟模式不能执行采集；真实模式也不开放定时调度、专题执行或专题公开。启动开发服务不会自动开启已有计划，定时分发入口在本地返回零任务。数据库、文件、Workflow 与生产隔离，供应商联网调用本身仍发生在外部服务。当前合成测试与页面检查不代替真实付费采集验收。

### 本地后台设置（2026-10-19）

以下为仅支持配置草稿时的历史范围；默认 `mock` 模式继续保留这些限制。真实能力由上节的显式 `real` 模式提供，不改写本次历史验收记录。

旧本地启动器缺少接口白名单和自动任务专用连接，模型配置又要求本地禁止执行的能力测试，因此页面不能完成首次配置。本次将“配置草稿保存”和“真实执行”区分开：

1. `/admin/ai` 可保存连接，API Key 可留空；无密钥连接保持禁用。预设域名由本地启动器显式提供：`openrouter.ai`、`ai-gateway.vercel.sh`，不读取生产环境配置。带密钥的既有连接更换端点仍必须更换密钥。
2. `/admin/ai/profiles` 可选本地连接，手填模型 ID 和提示词，保存及修订未验证草稿；不读取供应商模型列表、不伪造能力测试，不把草稿标记为可执行。
3. `/admin/sources`、`/admin/topics` 可引用当前草稿修订，保存、读取、修订及软删除本地配置；关键词仍可选，专题仍须选择有效领域。旧 Profile 修订或连接引用不一致时拒绝保存，避免悄悄引用已改变的配置。
4. 本地自动采集、专题生成、定时执行和真实 AI 测试保持关闭；即使误设执行环境开关也拒绝运行。要验证生成／审核／发布流程，请使用下文的固定本地模拟资料与 Profile，不是刚保存的供应商草稿。

已有本地环境需先运行 `pnpm local:db:init`，再停止并重新启动 `pnpm local:dev`，让新增连接和白名单生效；不是要求配置 Vercel 或 Neon。数据库、页面表单及刷新读回的本次验收记录见[本地设置验收](local-evidence/2026-10-19-admin-settings.md)。

### 模拟闭环验收（2026-10-18）

使用仓库 [本地联调资料](fixtures/local-signal.md)，按以下顺序操作：

1. 打开本地后台，在手动导入页上传 `docs/fixtures/local-signal.md`，检查批次状态、解析内容及原件清理结果。
2. 在 AI 信号生成页选择该资料和“本地模拟 · 无 AI 调用 · 非真实模型”配置，创建并执行任务；检查进度、结果和零供应商调用。

4. 在本地信号列表、详情、雷达和搜索中核对公开结果，再从后台撤回，检查公开读取不再显示该条信号。

模拟器只识别该资料模板的标记和字段，**不是通用新闻抽取算法**。普通文档可以参与解析验证，但不会自动得到真实 AI 结论；没有符合模板的内容时可返回零候选。固定 Profile 的“就绪”只表示本地模拟可运行，不是供应商能力测试通过，不生成或伪造供应商账单。

此前本机已完成：新增后台角色真实登录与精确权限核验；旧令牌版的真实 HTTP 登录、上传、Docker 解析、原件立即清理、Workflow 模拟生成、人工确认发布、详情／列表／搜索读取、撤回及详情 404。浏览器检查覆盖旧登录、生成列表、候选详情、发布标记、撤回按钮及窄屏页面，未发现页面脚本异常；不是所有后台页面的自动化浏览器全覆盖。本次免令牌后台访问、同源读取、错误 Host／Origin 拒绝已独立复验，没有为认证修改重复生成或发布。两条虚构测试信号最终均已撤回，资料、虚构实体与审计记录只留在本机，禁止同步为生产内容。详见[本地验收记录](local-evidence/2026-10-18-backend.md)。

模拟器不调用供应商，不产生真实 AI 费用；为保持原任务引擎门禁，账本仍会保留最低 **1 微美元（$0.000001）模拟记账**。它不是供应商实际账单，也不应改写成供应商返回了零费用。

也可以使用可复跑的真实 HTTP 联调脚本。它不接受令牌参数，不读取登录文件或使用 Cookie，默认只访问 `http://127.0.0.1:3000`。在任何业务写请求前，先检查数据库健康和伪造转发 Host／错误 Origin 被拒绝；这些只读检查通过后才上传新的虚构联调资料。认证调整后的脚本尚未实际重跑，原完整闭环验收记录保留为历史证据。

```bash
pnpm local:dev:smoke
# 如服务使用 3001 端口，追加 --port=3001
```

脚本在上传资料标题中加入随机联调编号，使用真实 HTTP、数据库和 Docker 解析，生成阶段仍为明确标记的模拟器；逐步核对公开详情、列表、搜索以及撤回后的 404。它不测试浏览器交互布局，不调用真实 AI。每个写请求只发送一次，发生失败或结果未知即停止，不自动新建任务或重新发布；请求编号和安全阶段状态保存在 `.hzense-local/smoke-*.json`，不保存 Cookie、正文或密钥。若发布后中途失败，本地测试信号可能仍公开，应根据该回执在本地后台核对并撤回。即使脚本通过，任务／候选／发布撤回历史也保留在本地库，不执行删表或清库。

## 尚未本地化的能力

- 真实 AI 模式的实际供应商端到端验收与最终账单对账；合成响应测试不代替真实模型验证，不继承生产 Key。
- 自动采集的定时调度与专题洞察执行器；本地只支持手动启动采集，不派发 GitHub Actions 或云端采集任务。
- AI 补全、来源独立核验等额外执行器；当前模拟闭环验证人工确认发布，不假装已完成上述能力。
- 生产内容与本地数据的受控导入／导出。当前没有自动双向数据同步，也没有将本地开发卷上传覆盖 Neon 的入口。

## 提交、部署和发布

1. 本地修改代码并完成对应层级验证；代码和测试仍在当前仓库。
2. 提交 PR，评审和 CI 通过后合并、同步本地 main。
3. 合并后沿用 Vercel 的部署流程；若远端不可用，明确记录待部署／待验收，服务恢复后针对同一提交重试。
4. 生产数据库需要变更时，仍单独走受保护维护，不运行本地生产 SQL，也不将本地数据卷上传覆盖生产。
5. 确认域名、部署版本、数据库迁移／权限与业务链路后，再进行正式内容发布。代码已部署不等于内容已发布。
