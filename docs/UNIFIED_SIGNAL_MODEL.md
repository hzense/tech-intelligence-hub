# 统一 Signal 逻辑结构

本文件定义公开网站消费的 **统一逻辑模型**，不宣称三个现有来源已经合并为同一张物理表。正式数据库搬迁、生产权限和读模式切换另行实施与验收。代码契约位于 [`apps/web/lib/unified-signal-core.ts`](../apps/web/lib/unified-signal-core.ts)。

## 一条 Signal 的共同字段

| 组         | 字段                                                              | 含义                                                                                                                                                                |
| ---------- | ----------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 身份与正文 | `id`、`title`、`summary`、`type`                                  | 稳定页面 ID、标题、摘要、事件类别；未分类时 `type` 为 `null`，不把人工确认方式冒充事件类别。                                                                        |
| 时间       | `occurredAt`、`capturedAt`                                        | 事件发生时间与系统采集／发表时间分别保留；不可用采集日期填造事件日期。                                                                                              |
| 发表       | `publication.basis`、`state`、`version`、`revision`               | 明确区分历史 Seed、来源证据合格发表、管理员确认；归档不等于当前公开。版本号不适用时为 `null`。                                                                      |
| 判断       | `assessment`                                                      | 仅原记录有重要度、置信度和新颖度时给出三值；置信度表示新闻可信程度，并非未来结果发生概率。人工确认记录为 `null`，不补零或推算。                                     |
| 关系       | `people`、`organizations`、`relatedEntities`、`topics`、`sources` | 集合字段始终存在，可为空；`relatedEntities` 保留历史 Seed 中的模型、论文、产品等非参与者引用，不把它们冒充人物或组织。仅人工确认的名称保留 `name`，`id` 为 `null`。 |

`publication.basis` 的值为 `legacy_seed`、`source_evidence`、`manual_confirmation`。`legacy_seed` 只代表旧档案来源，不能推导出新发布资格；`manual_confirmation` 代表管理员确认，不代表独立证据核验。当前发表资格仍由各自受控公开读取路径决定，统一模型只映射它们返回的公开数据，**不会自行授予发布权限**。

## 来源适配与读取

| 现有来源     | 原始位置                                                                                | 统一映射                                                                                                        |
| ------------ | --------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| 历史 Seed    | `data/seed/signals.yaml`                                                                | `legacy_seed` / `archive`；保留重要度、置信度、新颖度与事件／采集时间，按现有实体／来源／专题目录解析显示名称。 |
| 证据合格发表 | `public.current_public_signals`，其底层为 `signals`、`signal_versions` 及关系／发表记录 | `source_evidence` / `published`；人物、组织使用可公开的实体 ID，评分来自实际版本。                              |
| 人工确认发表 | `public.editorial_public_signals`，其底层为追加式 `editorial_signal_revisions`          | `manual_confirmation` / `published`；无评分、无已核验实体 ID，来源链接可为空。                                  |

信号卡片、详情、当前／档案判定、雷达重要度读取共用这一适配契约。历史 Seed 的引用由一次投影解析名称与类型；未登记人物保持空数组，非参与者实体保留在 `relatedEntities`。人工确认的姓名／组织名在卡片及详情显示为文本，不再把 `person-0`、`organization-0` 等位置编号当成实体页链接；信号页可以按名称筛选，但该筛选键不是实体身份，也不会进入资源目录。未来完成实体登记后，须由经过验证的关联流程授予真实 ID，不能凭同名自动合并。

现有历史 Seed 的逐条投影由 `apps/web/test/legacy-signal-projection.test.mjs` 核对 ID、时间、保留的评分、来源、Topic、实体引用与事件角色；缺失引用或把非参与者实体标成角色会失败，而不是退化显示原始 ID。移除 2026 年以前的 11 条后，当前 Seed 有 71 条旧 `accepted` 信号；对[已补充的记录](content-intake/2026-09-27-signal-entity-backfill.md)逐条核对来源后，仍有 4 条缺已登记人物。SemiAnalysis 作为信息源而非相关公司纠正后，原关联它的 17 条记录中有 15 条不再有关联组织；不为填满组织字段而补造事件参与者。剩余人物和组织空缺不能视为满足新人工发布条件。原 5 条 Seed Radar 快照只引用已移除信号，已随之撤下，不能沿用旧评分。

人工确认内容仍按原表单校验标题最多 80 个 Unicode 字符、摘要最多 500 个 Unicode 字符，发布时至少有日期、一个人物名称、一个组织名称和一个领域。历史记录按各自原始契约读取，不静默截断或补造字段。

## 后续物理迁移边界

`strength` 已退出当前 Seed 与统一公开 Signal 契约；既有数据库表、不可变历史版本及旧发布写入契约仍保留该物理列，直到单独设计并授权生产迁移。本次没有改写旧版本、伪造替代评分或修改生产数据库。现有 `confidence` 数值原样保留，并未重新校准其可信程度。

如需把来源真正迁入一个数据库权威，须另设受保护的迁移：先审计旧 Seed 与当前发布记录的稳定 ID、事件时间、来源、人物／组织身份、撤回历史和评分缺失，再定义目标 Schema、可逆对账及读切换。不得将缺失来源链接、未核验人物关系或不存在的评分用占位值填入旧 `public.signals` 的 `NOT NULL` 字段；不得复制一条发布记录却遗漏其撤回修订。没有生产备份／恢复方案和明确授权时，不执行写入式回填或删除旧表。
