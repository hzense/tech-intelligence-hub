# 导入原件确认冲突诊断

## 已有证据

- 用户报告手动上传返回 `document_conflict`；两个最新文件批次停留在“等待原件”。
- PR #108 对应生产部署成功，上传授权请求 200，原件确认与上传回调 409；尚未进入解析或 AI 生成。
- 原有多个校验分支共用错误码且无细分日志，不能据此断定 ETag、字节数或回执中的哪一项不一致。

## 诊断变更

- 保留路径、大小、版本与回执的完整性校验；增加固定白名单原因码，区分 Blob 路径／大小／状态／ETag、读取字节数及数据库回执／声明冲突。
- 响应与日志不记录文件名、对象路径、正文、哈希、ETag 值、连接串或凭据；任意第三方错误信息不得穿透。
- 前端仅在确认返回 `source_unavailable` 时尝试上传；校验冲突、认证／服务故障等停止重传，不再统一承诺再次提交可续传。
- 评审补充：过期原件独立返回 `source_expired`，即使对象仍在存储中也不重传覆盖；不新增删除行为。
- 未修改数据库结构、角色权限、预算、解析／AI 开关或原件清理策略。

## 验收边界

代码测试不能代替生产根因确认。部署后仅对现有等待原件批次进行原件确认，读取固定原因码；不重新上传、调用解析器或 AI，不删除批次。根因与修复结果须另行记录。
