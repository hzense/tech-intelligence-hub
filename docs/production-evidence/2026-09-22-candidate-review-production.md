## 独立迁移授权

`0020–0021` 使用一次性策略 `accept-unverified-candidate-review`，不会复用 `0019` 的授权。维护工具固定完整 22 项迁移清单，并将审批绑定到：

1. 生产数据库 host、port、database、认证 user 的目标指纹；
2. 已审阅备份标识的 SHA-256；
3. 完整迁移清单指纹；
4. 实际待执行的尾部迁移集合及计划指纹；
5. 当前 `main` 提交、GitHub Actions run/attempt 和限时审批。

若生产已部分执行 `0020`，门禁只允许剩余 `0021`；空计划、夹带旧迁移、未来迁移、文件或 checksum 漂移、目标/备份变化均拒绝。DDL 前会在迁移锁内再次读取认证身份和冻结执行产物。
