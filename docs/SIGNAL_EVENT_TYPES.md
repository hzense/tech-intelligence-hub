# 信号事件类型

`type`（生成结果中为 `signal_type`）只描述**发生了什么事件**，每条新信号选择一个核心事件类型。技术领域由 `topics`／`topic_ids` 独立表达，可以多选。类型不表示来源可信度、发布方式或内容开放程度。

## 当前可选类型

| 标识          | 展示名称       | 适用事件与边界                                                                                             |
| ------------- | -------------- | ---------------------------------------------------------------------------------------------------------- |
| `research`    | 研究成果发布   | 论文、研究报告、测试或评估结果公布；安全研究报告也属于本类。                                               |
| `product`     | 产品发布与更新 | 产品、模型、软件版本或服务上线，以及产品量产发布；开源发布仍按核心产品事件分类。                           |
| `funding`     | 融资           | 融资轮次、募集资金；企业使用自有资金建设设施不属于融资。                                                   |
| `acquisition` | 收购合并       | 企业、业务或资产收购与合并。                                                                               |
| `hiring`      | 人才招聘       | 招聘计划、岗位招募或团队扩招；具名人物已就任属于人事变动。                                                 |
| `policy`      | 政策发布       | 政策、产业规划、扶持措施发布；具体调查、执法与处罚属于监管行动。                                           |
| `people`      | 人事变动       | 具名人物加入、离职、任免及职务变化。                                                                       |
| `patent`      | 专利进展       | 专利申请、公开或授权；不把专利授权等同于产品实现。                                                         |
| `partnership` | 合作签约       | 明确的合作协议、联合研发或商业合作，不根据同篇报道同时出现推断合作。                                       |
| `regulation`  | 监管行动       | 监管调查、执法、处罚、审批与具体合规决定。                                                                 |
| `disclosure`  | 经营与信息披露 | 财报、经营与行业统计、商业声明、风险公告；其他事件已有明确类型时优先采用对应类型，不把所有新闻都归到本类。 |
| `operations`  | 建设投产       | 基地或设施的建设规划、开工、扩产、投产或停产；必须在标题与摘要中区分规划、在建和已投产。                   |
| `incident`    | 事故事件       | 已发生的故障、攻击、泄露及其他事故；风险推测和潜在攻击研究不属于已发生事故。                               |

这些类型围绕核心事件划分，不保证一篇原文只包含一个事件。一篇报道同时包含多个独立事件时可以拆成不同信号；不拆分时选择标题和摘要的核心事件，不填多个类型。

`technology`、`security`、`market`、`supply_chain`、`open_source` 退出新事件分类。技术和安全主题通过已启用的领域目录表达；开源、供应链等背景可在标题与摘要中说明，不新增任意 `topic_id`，也不额外要求填写属性标签。

## 代码与存量兼容

- `packages/ingestion/src/signal-types.mjs` 是新事件类型、中文名称和生成规则的公共定义；`SIGNAL_EVENT_TYPES` 为 13 类。
- `LEGACY_SIGNAL_TYPES` 固定旧 15 类，历史生成契约继续按当时的类型集合解析。`SIGNAL_TYPES` 是兼容存储读取的 18 类并集，不是后台可选项。
- 新任务固定 `output_contract=signal-event-types-v1`，继承原文发布日期与资源证据规则，只接受 13 种事件类型。旧任务的候选、材料哈希、费用和成功回执不改写，也不重新调用 AI。
- 后台新建／更新草稿、确认发布只接受当前事件类型；旧类别的已发布信号仍可查看、按原请求重放和撤回，修订时明确选择新类型。
- 公开卡片、详情和搜索投影共用事件类型解析。已逐条核定的 26 条 Seed 分类保存在 `data/seed/signal-event-classifications.json`；只有 ID、原类型、标题和摘要全部相符时才使用该映射。其他旧类别显示为未分类，不根据关键词推断事件。
- 原始 `data/seed/signals.yaml`、历史归档清单、数据库快照和来源证据保持原字节。上述映射只影响展示和新搜索投影，不声称生产存储已完成重分类。
- `0033_signal_event_types.sql` 只给物理枚举追加 `disclosure`、`operations`、`incident`，不删除旧值、不修改数据或权限。当前 v4 发布使用 JSONB，新应用兼容仍处于 `0032` 的生产库，可以先部署；旧 v3 枚举列写入新增三类、完整 Schema 核验则须先按受保护维护流程完成 `0033`。本地隔离测试通过不等于生产已升级。旧生产搜索索引须随正常同步更新后才包含新分类词。

26 条历史分类依据及范围见[分类核定记录](content-intake/2026-11-02-signal-event-types.md)。
