## 自动检查后发布与事后管理（2026-10-21，本地验证通过，默认关闭）

新流程为：生成并保存候选 → 独立自动发布步骤 → 合格者公开，缺项者待处理。生成 `completed` 不等于已发布；缺日期、资源资料、领域或可披露来源的候选仍保留，不编造人物、不额外调用模型补齐。

- 生产自动发布要求 `HZENSE_AUTOMATIC_PUBLICATION_ENABLED=1`，且要求人工发布基础开关、统一存储已启用。手动生成页面仍需此显式开关与包含自动发布含义的任务授权，保存 `automaticPublicationConsent`；旧客户端不携带此项时只生成私有候选，开关变化不会扩大原有授权。本地真实 AI 的自动采集可直接在配置页保存发布方式，不再要求 `--auto-publish`；严格本机数据库隔离与真实模式检查仍保留。
- 新任务将 `{mode: 'automatic', policy: 'auto-publication-v1', sourceUrls: [...]}` 固定在原始快照。只允许经过归属、来源版本、内容指纹核对的公开网页原始链接；文件、受保护链接和未知来源不自动公开，模型生成的 URL 不作为授权。自动采集的新生成任务仅在父采集任务快照 `publicationMode: 'automatic'` 时得到授权；缺失字段视人工审核，不读取后来改动的配置来扩大授权，历史生成任务不补发。
- 自动发布独立于付费生成，发布步骤失败最多重试三次，不再调用 AI。每条候选使用稳定请求号，数据库串行检查首修订；人工草稿、修改、撤回不会被覆盖或自动重新发布。异常可从信号管理点击“重试本任务自动发布（不调用 AI）”，仍执行相同门禁。
- 预览和实际写入都重新核对补全／补证资料；读取失败不自动降级成原候选并发布。生成、历史查询及补全读取共用进程级单连接池，跨 Next.js 路由模块与开发热更新复用，仍逐次执行各自权限核验，不提高数据库账号的连接上限或权限。
- 后台信号管理可修改标题（80 字）、摘要（500 字）、日期、事件类型、领域及已有来源／资源身份选择。保存修改生成新版本；撤回从公开信号、搜索、雷达与资源关联中移除，历史仍保留。原始候选快照只作为辅助依据，不冒充最新正文。关联资源的姓名、简介与原文证据仍受原材料约束，不能任意伪造实体。
- `automatic_checks` 表示通过结构、证据引用和发布完整性规则，**不表示事实已被独立核实**。人工修改后记录 `manual_confirmation`；缺少来源日期或人物依据时不会用运行日期／猜测身份代替。
- 需新迁移 `0032_automatic_signal_publication.sql` 和明确的最小 ACL 升级，再启用开关。迁移不会回填或公开历史候选。本次开发不执行生产迁移，不开启生产开关，不运行真实付费验收。

下方带日期条目保留原阶段记录；关于新任务人工确认要求，以本节的显式开关与授权策略为准。

自动发布内核开发时 `pnpm local:verify --build` 通过：Web 1,080 项通过／14 项环境测试跳过，数据库默认 3,137 项通过／881 项环境测试跳过；另按组执行真实 PostgreSQL 集成测试 919 项通过。浏览器合成生成工作台回归 62 项、发布编辑回归 2 项通过；Chrome 实际本地页面已确认标题／摘要可编辑、旧补全读取警告消失、历史任务保持未授权自动发布。后续采集页面发布方式增量及最新验证范围见 [PROGRESS.md](PROGRESS.md)。以上不包含真实付费生成或生产自动发布验收。

## 信号日期改为原文发布日期（2026-10-21，本地验证通过，未提交／未部署）

按操作者确认，后续新生成信号的日期使用**原始新闻／文章的首次发布日期**，不再使用正文事件的发生日期，也不使用管理员在 HZense 点击确认发布的时间。该日期用于信号日期展示和排序；本站发布与记录时间继续独立保存。

- 新建任务固定 `output_contract=signal-source-publication-v1`，候选必须携带 `date_basis: source_published`，发布材料保存对应的 `dateBasis`。资源、类型、领域、逐字原文证据和人工确认要求继续适用，不新增模型调用。
- 同一篇原始文章提取出多个候选时，共享该文章的首次发布日期。日期必须由原文明确的完整年月日支持，引用使用已保存的来源片段；不能把正文事件日期、仅含月日的描述、文章更新时间、搜索发现日期、采集日、上传日或运行日补成发布日期。只有更新时间或日期仍有歧义时保持 `null`。
- 日期未知仍可保存为私有待补全候选，并保留通过原文匹配校验的辅助引用和 `needs_event_time` 兼容缺项标记。辅助引用不代表日期已确定；确认发布前，管理员须补齐并确认原文发布日期。日期非空而缺证据、伪造引用和非法日期仍拒绝。
- `event_date`、`eventDate`、`occurred_at` 暂留为兼容字段名，日期含义由保存的契约／日期依据标识决定，不能仅按旧字段名理解为事件日。本站 `published_at`／`recorded_at` 不承担原文发布日期的含义，也不会被这次调整改写。
- 旧任务按已保存的输出契约和原始快照执行／读取；旧候选、材料哈希、费用及历史发布记录不自动迁移或改值。未携带新日期依据的旧记录继续保留原事件日期语义，不能把历史日期直接重命名为原文发布日期。原文日期缺失的历史候选也不会因这次修改自动补齐或重新调用 AI。
- 补证流程传递 `dateBasis`，只在同一日期语义下补齐空值，不用旧事件日期覆盖新原文发布日期。新日期契约不能进入仍按事件日期处理的旧 qualified 新增核验、转换及发布路径；旧记录的幂等回放、读取和撤回继续保留。

## 日期未知时保留私有待补全候选（2026-10-21，本地修改，未部署）

本节记录改用原文发布日期之前的事件日期修复。保留私有待补全候选的机制继续适用，后续新任务的日期含义以上一节为准；旧任务仍按原契约理解日期。

模型仍应在不能确定事件日期时返回 `event_date: null` 和 `event_date_evidence: []`。若模型却附带了日期相关引用，私有候选评估会先核对每条引用的片段编号和逐字原文：全部合法且其他候选字段通过时，保留正文和引用，日期仍为 `null`，标记 `needs_event_time`。这些引用仅是辅助材料，不等于确认了日期；不会从文章发布日期、采集时间、运行时间或引用内容自动推断日期，也不会额外调用 AI 修复。

候选卡片显示“日期尚未确认，待补齐”，并将引用标为“日期相关辅助引用（日期待确认）”。保存和审核重新核对原文与缺项，不能通过删掉标记绕过校验。严格补全契约不放宽，正式发布仍要求管理员补齐并确认有效事件日期；日期非空但无证据、引用伪造、格式错误等仍拒绝。

无数据库迁移、预算／模型／生产配置改变。旧失败任务的候选正文没有保存，不能恢复为候选；保留原失败记录及费用，不自动重试。该修复不包含 HTTP 403 备用来源处理，也不改变模型合法返回空候选数组的行为。

## 资源缺项保留为私有待补全候选（2026-10-20，本地修改，未部署）

仅当 `resources` 是合法数组、已有条目及所有其他候选字段与原文引用均合格，但尚未覆盖人物、组织或人物所属组织时，保留正文和已有资源，标记 `needs_resource_details`，供审核补全。缺项不是事实核验通过，也不是发布许可；不猜测身份、不伪造证据、不自动再次调用模型。缺少 `resources` 字段、类型错误、重复或额外资源、引用不匹配等仍拒绝该候选。

保存时重新计算标记；审核读取重新核对原文与材料哈希。补全仍使用严格完整性校验，发布服务按原始候选及当前补全材料重算缺失项，服务端拒绝缺项发布；不能通过删短人物／组织名单绕过。完整补齐后解除门禁，草稿保存、撤回和历史幂等回执不受影响。候选快照与当前补全／发布状态分开显示。

无数据库迁移、预算调整或旧任务改写。历史被拒绝项只保存诊断、没有原正文，无法用本次代码恢复其内容；新规则适用于后续生成，不自动重跑旧任务。

## 本地真实 AI 模式（2026-10-20，本地开发验证通过）

- `pnpm local:dev` 默认保持模拟生成；显式 `pnpm local:dev --ai=real` 才读取本地保存的真实 Profile 和连接。需要先在本地 AI 后台启用连接、完成所选模型的必要能力测试并保存就绪配置；原来的未验证草稿不能直接执行。
- 真实本地生成复用现有来源快照、结构／证据校验、修订检查、幂等、预算、费用和候选存储。单批上限为 5 美元，UTC 每日生成预算为 10 美元；连接能力测试费用另行记录。API 返回费用缺失时仍使用现有估算，不把估算称为供应商最终账单。
- 任务由本地 Workflow 执行，不调用生产派发器或云端 Sandbox；数据库、加密 Key 与资料均使用独立本地存储。只有用户明确授权并执行后，所选解析资料才会发送给配置的供应商；调用需要联网并可能收费。任务和候选不会自动同步或发布到生产。
- 模拟任务与真实任务不得跨模式执行。切换模式不重建历史任务、不改写费用、不自动重试未知结果；切换前须核对在途任务。手动启动的自动采集随后已接通，定时采集、专题自动执行与 AI 补全仍未本地化。
- 全量检查与构建、隔离 PostgreSQL 集成和合成浏览器回归已通过，真实模式页面与只读 API 已在本机核对。初始验收没有付费模型调用；用户随后实际执行时先后遇到资源缺项拒绝和原文 HTTP 403，尚不能宣称真实采集闭环通过。合成响应回归不能证明真实供应商模型成功、费用准确或内容可发布。详见[验收记录](local-evidence/2026-10-20-real-ai.md)；启动与配置步骤见[本地真实 AI 说明](LOCAL.md#本地真实-ai-配置与执行2026-10-20)。

## 资源约束与失败诊断（2026-10-13，本地修改，未部署）

针对生成后资源校验拒绝，系统提示与 Schema 描述明确：`resources` 只能且必须覆盖当前候选的 `persons.name`、`organizations` 和非空 `persons.organization`，不能加入背景资源、信息源或其他候选的实体。关联字段采用一致的原文名称；不自行翻译或扩展简称。每个资源自己的至少一条原文引用必须包含该资源完整名称，不能借用其他资源的引用或将 `Anna` 当作 `Ann` 的证据。简介与事件角色仍只填有依据的信息，否则为 `null`。

本节记录 10 月 13 日的严格策略；仅资源覆盖缺项的处理已由上方 10 月 20 日规则更新。非法资源或证据仍拒绝对应候选，同批其他合格候选继续保留。不静默删除模型已输出的资源或猜测身份，不自动调用 AI 修补。标题 80、摘要 500、最多 5 条候选与输入／输出、预算和租约限制均不变。

| 错误码                           | 含义                                                        |
| -------------------------------- | ----------------------------------------------------------- |
| `generation_invalid_json`        | 模型正文不能解析为完整 JSON，例如夹带说明、围栏或多个对象。 |
| `generation_invalid_envelope`    | JSON 顶层不是约定对象，缺少或多出字段。                     |
| `generation_invalid_candidates`  | `candidates` 不是有效数组。                                 |
| `generation_too_many_candidates` | `candidates` 超过 5 条。                                    |
| `generation_invalid_reason`      | `reason` 类型、非空、字符或长度不符合约定；不保存其原文。   |
| `generation_output_too_large`    | 整份结果超过 400,000 字节安全上限。                         |

候选内部失败仍使用 `generation_invalid_output` 和既有逐字段诊断；`resources[N].name / missing_evidence` 明确显示为“引用未包含该资源完整名称”，与证据数组为空区分。达到输出 token 上限仍优先记录 `generation_output_truncated`，不会误报为 JSON 错误。

只保留固定分类与白名单字段，不保存供应商错误、原始响应、推理过程或被拒绝候选正文；已观测的使用量和 API 费用继续进入原账本。旧失败记录不改写、不推测补填原因，不自动重跑。本批不新增数据库迁移、权限或生产配置变更；离线合成测试不代表真实模型成功率或已上线。

## 生成任务的发布标记（2026-10-09，本地修改）

生成状态与发布状态分别展示：任务列表增加“发布情况”，汇总候选数、已发布数、未发布数（包括已保存草稿）及已撤回数；候选卡片显示“未发布”“草稿 · 未发布”“已发布”或“已撤回”。只有当前已发布项提供正式 Signal 链接，已发布／撤回项可进入原候选的发布记录。

状态按管理员、任务 ID 和候选原始索引，从 `editorial_signal_revisions` 最新修订批量读取，不按卡片数组位置匹配。该流水在统一存储启用时通过现有事务触发器同步 `signals`／`signal_versions`；不修改生成时的私有 `result`、材料哈希或费用。候选正文继续明确标注为原始 AI 快照，不能把它当作人工修订后的正式正文。

读取失败、任务归属／可见性变化或无法识别的旧候选显示“发布状态待核对”，不默认为未发布，也不隐藏已有生成记录。读取不依赖生成及人工发布的执行开关，不增加生成角色权限。审核后可使用列表的“手动刷新列表”或详情的“刷新任务与发布状态”只读核对；刷新不调用 AI、不重新发布或撤回信号。本批不包含生产数据写入、迁移或部署。

## 信号与资源同次生成（2026-10-04，历史版本）

该阶段新任务采用 `output_contract=signal-resources-v1`；后续 `signal-source-publication-v1` 继承本节资源规则，并按文首规则区分日期含义。一次提取请求同时返回信号、事件类型、领域和 `resources` 草稿；不会为了创建人物或组织再发出一次模型调用。资源草稿与候选一同保存，刷新、审核、补全和重试均读取已保存的版本。

每份资源草稿包含 `type`（person/company/institution）、`name`、可空的 `introduction`、可空的 `event_role` 和至少一条 `fragment_id/quote` 原文短引。资源须覆盖候选人物、组织及原文支持的人物所属组织；名称和引文接受校验，简介与身份含义仍须在确认页核对。无依据的简介或角色为 null，原文未提供人物时保留空人物列表，不推测负责人、职务、官网、头像或任职关系。来源 URL 使用确认页提供并由管理员选择的公开导入来源，AI 不生成 URL。

确认页把资源展示为“新建”“复用”或“需确认”，并列出简介、事件角色和原文证据。后端用规范化名称及已登记别名匹配当前数据库和可信 seed 目录；唯一匹配自动预选，多个匹配必须明确选择。同名不同身份可以明确选择“新建独立资源”，唯一匹配也保留这一选择。公司和机构的类型冲突也必须确认已有身份，不能通过改一个类型重复建档。新契约的名称由资源草稿决定；历史任务仍保留原姓名编辑方式。每份资源必须选中至少一项支持其引用证据的公开来源，不能用信号的任意 URL 代替；补证资料按片段来源独立映射，AI 和浏览器均不能指定权威出处。组织、日期、事件类型与领域仍按现有规则校验；没有人物证据不阻止这类新任务发布。

补全新增的人物和组织会同步进入已经保存的确认草稿，并保留人工选择的日期、类型、领域、来源和既有身份；已公开记录需再次确认发布才更新。原文后来不可读时，仅允许同一 canonical 身份且简介、角色、名称、类型和引文均未变化的资源保留最近发布／撤回版本的来源；草稿里提交的来源声明不能替代证据。

一次确认发布在同一个数据库事务中完成以下步骤：

1. 校验管理员、候选材料、当前修订、公开来源及原始资源草稿绑定。
2. 持有与材料登记共用的目录锁，重新检查匹配，复用明确选定的实体或分配稳定 ID 并创建实体及对应人物／组织类型记录。若预览后有另一请求创建了同名实体，要求重新确认身份，不自动合并。
3. 将最终 ID、资料、事件角色、证据和信号一同写入不可变的发布修订；失败整体回滚，相同请求返回原回执，并发发布不重复建档。

资料版本存于已有 `editorial_signal_revisions.content.resources`，复用 `entities`、`person_profiles`、`organization_profiles`，不新增第二套实体表。既有实体元数据和独立整理的静态简介不被自动覆盖。公共读取只投影当前已发布修订，提供资源目录、详情、筛选和双向关联；公开 DTO 不带私有原文片段。撤回后该修订的资料不再参与投影，仍被其他已发布信号引用的资源保留，共享实体不删除。

旧的 metadata/topics/legacy 快照、材料哈希和回执不改写，不自动重跑或回填历史任务。此前只保存姓名的发布记录仍可通过当前唯一公开身份获得链接；新版本保存明确的 canonical ID，不因后来出现同名人物而改变已确认的身份。

本次无需新建数据库表或 DDL 迁移，但发布角色需要受保护的列权限升级，见 [线上维护](ONLINE_MAINTENANCE.md)。新代码接受升级前、升级后两套完整精确的角色能力；部分授权或额外权限仍拒绝。先部署兼容代码，再执行受保护授权与验证；授权完成前不将新资源发布视为可用。验证使用合成模型响应和本地隔离数据库，不代表真实模型质量验收或生产已启用。

审核页的资源目录预览使用已有读取授权的候选审核连接，不依赖发布账号的新增权限；读取失败仍明确报错，不能当作空目录并误判为新身份。发布能力单独核验：尚未授权时仍可查看、核对和保存补充，确认发布按钮禁用并说明原因。实际发布继续使用原发布账号及事务权限检查，预览不会新增任何数据库授权。

## 发布元数据贯通（2026-10-03，历史版本）

- 新任务以 `output_contract=signal-metadata-v1` 固定输出契约，在同一次生成中返回标准事件类型 `signal_type` 和领域 `topic_ids`。事件类型是研究、产品、融资等事件分类，与技术领域分别存储；确认页可修改，新发布必须选择类型。旧生成任务继续采用保存时的契约，旧候选和材料哈希不补写默认值；既有发布仍可读取、撤回和按原请求重放。
- 人物和组织按当前公开资源目录做唯一、同类型的名称或已登记别名精确匹配。公共列表、详情、筛选和资源反向关联使用同一投影；同名歧义或未建档名称保留文本，不自动创建实体，不推断负责人。历史已发布信号无需重写即可关联已存在资源。
- 确认页读取同一管理员、同一导入项且处理版本和正文哈希一致的原始 URL，作为待确认的来源选项；不会让 AI 编造来源。管理员勾选后才随信号公开。文件、内部地址、签名和受保护分享链接不提供公开选项；仅允许常见文章及追踪查询参数。链接标识导入来源，不代表独立核验或已检查最终重定向页面。
- 已保存来源可保留或取消；后续导入不可用不阻止撤回，旧请求先按原哈希返回回执，再对新写入检查当前来源许可。旧信号可在原确认页补选事件类型和来源并更新发布，无需重新调用 AI。
- 使用现有 JSONB 发布修订和已有读取权限，无数据库结构或权限迁移。验证使用合成输入，不需要修改生产信号或调用付费模型。

## 同次生成匹配领域（2026-10-03）

- 创建任务时读取与确认页相同的已启用领域目录，将 ID 和名称保存在任务快照中。普通生成在同一次模型请求中传入该目录，每条候选返回 `topic_ids`：最多 5 项、不得重复，只能选择目录内的 ID；没有合适项时保留空数组。目录、分类提示和 Schema 都计入完整请求的输入检查与费用预估，不增加第二次 AI 调用。
- 结果落库及打开候选时，重新对照任务保存的目录校验；确认页再用当前目录解析名称，过滤已经停用的领域。生成建议自动预选，可手动修改；历史补证结果和已保存的人工选择优先，包括人工清空后的空数组。
- 老任务继续采用原输出契约，不为旧结果补写字段或改动材料哈希。领域目录变化不会自动重建或重跑任务：重复创建返回首次保存的目录与费用预估，只有显式重新生成才使用当前目录；来源、模型配置、预算上限与原指纹校验仍保留。
- 本次无需数据库结构或权限变更；线上完整目录同步是独立的数据维护步骤。自动匹配只使用实际启用的目录，不会凭空启用仓库中尚未同步的领域。验证使用合成输入和响应，不调用真实模型、不回填历史任务。

## 100K 输入／50K 输出（2026-09-25，本地修改，未部署）

- 输入上限为 **100,000 tokens 的本地估算**，不是 100KB。统一使用 `gpt-tokenizer` 的 `o200k_base` 统计来源 JSON、提示词、供应商 Schema，并加 256 tokens 封装余量；不同模型分词不一致，实际使用量仍取 API 返回值。来源检查只报告来源估算，创建任务和发送前再次检查完整请求，不静默截断。
- 另保留独立安全边界：来源 JSON 1,000,000 字节、生成请求 3 MiB、供应商响应 1 MiB、候选 JSON 400,000 字节。这些不是 token 换算公式；补全请求仍是 256 KiB，能力测试仍是 32 KiB。
- 新提取配置默认 **50,000 输出 tokens**，提取阶段服务端及表单最大值同步为 50,000；其他阶段默认仍是 2,048、上限仍为 8,192。已保存配置及任务快照不自动覆盖，部署后须将目标提取配置保存为 50,000 的新修订，旧失败任务不自动重试。
- 普通候选补全及资料包补全仍采用独立的 48,000 字节来源限制，超限在创建任务前拒绝；执行器也复核历史快照，不外发、不误记为供应商结果未知。长资料生成成功不代表整份资料可直接用于补全，应先选择较小的补证资料包。
- 只接受一个完整的严格 JSON 对象，保留字段／引文／日期校验；不接受 Markdown 围栏、说明文字、截断 JSON，不保存推理通道。可选推理优先关闭；强制推理保留目录允许的最低强度并排除推理输出，不能保证免除推理费用。OpenRouter 目录声明的容量不够时在生成 POST 前停止。
- 仍最多 5 条候选、80 字标题、500 字摘要。批／日预算、25 分钟截止、权限与人工发布规则不变；更大的输出预留可能触发原有预算门禁。本轮没有调用付费模型、回填历史任务或变更生产配置。

## 调用费用（2026-09-21，本地开发，待发布）

- OpenRouter 信号生成和连接能力测试优先采用响应 `usage.cost`（账户扣费，不是 `upstream_inference_cost`）。合法的零费用同样有效；以美元换算为整数微美元，不足一微美元向上取整。
- 未返回有效费用、未收到响应或其他尚无明确费用语义的兼容供应商，保留现有保守预估口径：token 估算与预留金额取较大值。费用读取不发出额外模型调用，也不自动重试。
- 即使结构化输出校验失败，也保留已收到的 API 费用。任务过期、取消或数据库写入失败仍遵守原租约和幂等保护，不能保证费用已保存；需人工对账。
- API 费用可低于预留，预算门禁仍按 `max(预留,记账)` 计算，不因实际费用较低自动释放预算。
- 生成页面显示当前管理员的 UTC 当日信号生成记账合计及含预留的预算占用；包含已删除、失败记录，无列表条数限制，不含连接能力测试。页面打开或手动刷新列表时更新；查询失败显示不可用而不是零。
- 不回填历史记录，不将历史估算标记为实际费用。当前记账合计可能混合 API 费用和预估，不等于供应商已确认账单。无数据库结构或权限变更。

## 结果输出边界（2026-09-20，本地修复，待部署）

生成提示词明确要求仅返回最终结构化结果，标题、摘要和主张不得包含模型自述分析或思考标签。OpenRouter 请求使用 `reasoning.exclude=true`，其他兼容接口不发送该供应商专用参数；推理关闭策略见本页 2026-09-25 更新。SDK 只消费结构化结果，不保存独立 reasoning 内容。模型自由文本 `reason` 在持久化前替换为固定的有候选／无候选／校验未全部通过说明，避免把分析过程作为结果保存。结果组件不再直接展示历史 `reason`，旧记录及费用不改写；仍展示候选正文、日期、人物、原文证据和校验记录。

验证使用合成响应和本机浏览器，不调用生产模型。此修复尚未提交、合并或部署。

## 本轮范围

2026-09-17 增量接通“已完成的私有解析结果 → 当前 Profile 提取模型 → 持久化私有候选 → 后台查看”。入口为 `/admin/signal-generation`。这是第三阶段的 **3a 私有候选提取**，不是完整的 AI 事实核验或自动发布；不改变产品最终 `auto_publish` 默认策略。

本轮代码不会写入正式 Signal、Person、Evidence、核验批准记录或公开投影，不会切换公开网站的数据源。模型名称、人物角色、日期和断言仍是待核验建议；引用逐字匹配仅证明原文中存在这些文字，不证明断言成立。需要至少一位有证据的关键人物是公开资格要求，不是让模型凑人名的理由。

## 使用流程

1. 在批量导入页上传或接收链接，并完成解析。
2. 在候选生成页选择已完成的输入和当前就绪的 Profile。页面展示接收资料的供应商域名。
   可先点击“检查生成资料（不调用 AI）”：只读检查来源 token 估算、UTF-8 JSON 字节数、片段数、解析版本与前 3 个定位，不返回正文、不创建任务或预留预算。超出本页输入上限时提示拆分，不自动截断。选择另一份资料会清除旧检查；检查失败或超限时阻止创建。检查不是授权或发布资格，创建与执行仍重新校验。
3. 明确同意把所选私有解析正文发送给该供应商并产生费用，创建任务。此步骤不调用模型。
4. 显式执行任务，接口将既有任务排队并返回 `202`；后台 Workflow 提交租约和预算预留后进行一次模型调用。关闭页面不取消后台执行。
5. 查看持久化候选、原文短引、日期、人物与组织建议及缺口。新契约显示原文发布日期，旧任务保留事件日期含义；结果仅管理员可见，不代表发表。

页面刷新只恢复原任务，不自动生成。相同输入、解析版本、Profile 修订和生成版本不会因换 UUID 再次调用；失败和结果未知也不会自动重试。未知任务须人工核对，不能用删除会话存储或换编号“恢复”。当前只有手动执行，没有新增周期调度。

## 输入与输出契约

- 来源只从归属当前管理员、未取消且解析完成的导入记录读取；浏览器不能提供正文、凭据、模型参数或 owner。
- 服务端固定 `fragment-1…N` 编号并保留页／段／单元格定位。输入 token 与字节边界见本页 2026-09-25 更新；超过限制明确拒绝，不切片或静默截断。
- 一次最多 5 个候选，允许零候选并说明原因。新契约日期为原文首次发布的真实 `YYYY-MM-DD` 或 `null`，旧契约保留事件日期，不使用上传或运行时间补齐。模型应在日期未知时返回空日期证据；若附带合法辅助引用，按文首私有待补全规则保留，不视为日期已确认。人物可以为空，不推断 CEO 参与。
- 每条候选标题最多 80 字、摘要最多 500 字，按 Unicode 码点计数（汉字、标点、字母和空白均占额度），不是字节或 token。提示词、JSON Schema 与服务端校验共用限制；超限拒绝，不静默截断，不改写旧结果；整批输出受 400,000 字节安全上限约束。
- 新建 Profile 提取阶段默认上限 50,000 tokens，独立核验和专题分析仍为 2,048。执行和预算预留采用所选修订的实际值，不覆盖历史配置；已有配置需显式保存新修订。更高额度不保证生成 5 条，也不授权自动重试。

### 脱敏故障诊断

#### 生成时的证据要求（2026-10-03，历史事件日期契约）

本节保留旧契约的事件日期要求；`signal-source-publication-v1` 改为文首定义的原文首次发布日期。逐字引用、完整年月日和证据边界仍适用，不将两种日期语义混用。

日期、人物或主张出现在原文中，并不代表模型已经返回对应引用。`event_date_evidence / missing_evidence` 表示候选填写了日期但没有附上证据，不能解释成原文没有日期。

生成请求现在逐项说明：非空事件日期、每个保留的人物和每条主张必须带真实片段编号及逐字原文短引，并在配置提示词之后再次声明这些要求不可覆盖。事件日期与文章发布日期分开处理，年份须有原文上下文支持；缺少人物依据时省略该人物，不能确定日期时使用 `null + []`，没有可支持主张时返回零候选。提供一组虚构原文与完整结果仅演示引用格式，示例不能作为真实任务证据。

同样的语义写入证据字段的 Schema 描述，兼容层保留描述；供应商不支持的数组长度等关键字仍按现有机制转为文字提示。本地严格引用校验继续保留，错误输出仍拒绝，不自动补造引用、不自动调用 AI 修补或重试。提示词和示例计入现有输入预算。离线回归不等于真实模型成功，旧失败记录不会自动恢复。

#### 逐条候选校验（2026-09-19，本地修复，待部署）

- SDK 仍向模型提供完整严格 Schema，但本地 SDK 回调只接收有界 JSON 信封（`candidates`／`reason`、最多 5 条、总字节上限）。随后逐条执行原有字段、Unicode 字数、真实日历日期及逐字原文引用校验，避免一条业务校验失败让同批合格项全部丢失。非法 JSON、非法信封或整体超限仍整批拒绝。
- 系统提示明确：`event_date=null` 必须配 `event_date_evidence=[]`；有确定日期则必须有日期原文证据。按后续要求，标题上限由 50 调整为 80 个 Unicode 码点；摘要 500、输出 token 上限 8192 不变，不自动截短或改写模型内容。
- 新结果携带 `validation_version: 1`。`candidates` 仅包含校验通过但仍待人工审核的私有候选；`rejected` 仅记录原始零基序号、私有分类、拒绝状态和服务器固定字段／原因码，不保存被拒绝项的原始正文、供应商错误或凭据。后台按一基序号显示通过／拒绝数量和具体字段错误。
- 数据库写入前独立检查 v1 结果、拒绝项和错误项的精确字段，限制字段／原因码配对、集合大小、唯一连续候选序号、使用量以及终态一致性；混合完成与全部拒绝均适用，非法诊断在连接数据库前拒绝。存在拒绝项时，`reason` 替换为固定服务端说明并在保存层强制检查，不保留模型自由文本。合格候选在事务内绑定 owner 校验后的原任务快照，复用完整 Ingestion 合约检查全部字段、嵌套人物／主张／证据、篇幅、日期和逐字引用，且重新计算的审核缺口必须一致。旧无版本结果读取不受影响。

## 生成关闭时的线上只读连接预检

### 历史候选查看（2026-09-19 修复，待部署）

生成开关与历史读取分开：`HZENSE_SIGNAL_GENERATION_ENABLED=0` 时，已登录管理员仍可在 `/admin/signal-generation` 刷新任务列表、查询原请求和打开 `/admin/signal-generation/<任务 ID>`。详情直接展示摘要、事件日期、人物与证据，完整任务 JSON 可展开查看。

历史读取仅依赖专用生成数据库连接、Production 目标／TLS 校验和运行时角色最小权限检查，不要求 AI 密钥、导入配置或生成预算。记录仍按当前会话 owner 过滤，API 保留同源检查及 `no-store`；查询使用只读事务，不调用模型、不更新费用，也不顺带将过期 running 任务改为 unknown。这里显示的是已保存状态，过期执行的对账与恢复仍由受控执行路径负责。

创建、执行、取消任务与输入检查仍受原生成配置门禁控制。此修复不启用生产生成、不修改数据库权限、不公开候选。专用数据库配置缺失或权限校验失败时仍拒绝读取。

在 `/admin/signal-generation` 点击“运行只读连接预检”，显式同源 `POST /api/admin/signal-generation/preflight`，请求正文仅允许 `{}`。入口要求管理员会话、固定 Host／Origin、无查询参数；响应仅有六项布尔检查和固定错误码，使用私有禁止缓存策略。页面加载、链接预取和刷新不会自动执行预检。

预检只依赖 Production 专用连接与现有目标绑定，不要求开启生成、不要求配置 AI 预算。它建立短生命周期连接，验证实际客户端 TLS 证书、真实 `session_user=current_user`、目标数据库以及共享最小权限合约；事务显式只读，最后回滚并关闭连接，不读取候选正文，不调用任务列表的过期恢复，不访问 AI。相同服务实例内的并发预检共用一个在途检查，不产生多个同时打开的预检连接。

六项均通过仅证明本次生产连接预检成功，不证明 Profile 就绪、AI 费用已授权、真实模型验收完成或公开发布就绪。后续仍需独立确认预算与输入外发范围；不为测试连接提前打开生成。

**恢复流程修复（2026-09-20，本地实现，待部署）：** 创建明确被 `input_too_large`、`invalid_source`、`invalid_request`、`revision_conflict` 或 `task_deleted` 拒绝时，在当前标签页 `sessionStorage` 保存绑定完整原请求的固定错误码；已删除任务仅额外保存服务端返回的前序编号，不保存正文、凭据、供应商原始错误或外发同意。刷新后恢复拒绝原因及“核对并放弃未创建请求”入口；有前序编号时也恢复显式重新生成入口，但必须重新勾选授权并确认，且创建不调用模型。

恢复记录不代替服务器核验：放弃前仍需重新查询并得到 `404/not_found`，若任务已存在则恢复跟踪。每次重新提交创建前撤销旧拒绝记录，响应丢失或 `commit_unknown` 不得沿用旧记录解锁；存储更新失败时停止发送创建请求。记录损坏、输入不匹配或错误码不在白名单中时不提供放弃入口。旧版本遗留的请求若没有拒绝记录，页面明确引导先查询、重新勾选授权、使用原编号重新确认创建；不能仅凭一次 404 自动清理原编号，也不能偷偷换新编号或自动重试模型。

### 明确授权的重新生成

2026-09-19 起，按操作者要求，创建遇到已删除任务时可选择“重新生成（创建新任务，不调用 AI）”。确认后使用新的请求编号，固定关联服务端返回的原任务编号 `retryOf`；普通创建仍不能隐式重放旧任务。创建和执行分开，只有再次手动执行才调用模型，并可能再次计费。已删除的旧结果、状态及费用保持原样，批次、每日和连接预算继续计入旧费用。

服务端在所属管理员的事务锁内确认前序任务的资料、来源哈希、解析版本和 Profile 修订一致，且已终止、执行租约到期。重新生成使用 `基础版本/retry/前序任务编号` 作为执行版本；原唯一索引为同一前序任务去重，即使并发提交不同请求 UUID 也只创建一个新任务。该版本同时保存于既有配置快照，并通过 `retry_of` 返回关联编号，无需迁移、改索引或扩大数据库角色权限。响应丢失和刷新沿用新编号，绝不自动创建下一次尝试；重试本身再被删除时也需要另一次明确操作。取消但从未执行的任务仍按原规则处理。

### 任务恢复与派发隔离（2026-09-28）

- 列表中的已终止且租约到期任务直接提供“重新生成”。选择后展示原资料和 Profile 修订，重新确认授权再创建；旧任务、发布关联、结果和费用保留，无须删除。刷新未提交的选择不会创建任务，已提交请求仍沿用同一 UUID 恢复。过期 running 任务在显式重建事务内按既有规则转为 unknown，费用不变。
- 创建明确被资料重复、来源不可用／取消、配置未就绪、连接不可用、前序任务仍受保护或记录不存在拒绝时，保存拒绝原因并允许核对后退出。退出仍须重新查询同一 UUID 并确认 not_found；网络错误、commit_unknown、身份冲突和未知错误不能借此清除请求。
- 每次手动派发在行锁内生成严格递增、毫秒精度的 queued 时间，以既有 `progress_at` 作为本次排队的版本凭据，传入 Workflow 和私有 Worker 文件。启动前核对版本，领取时在同一事务中再次核对；旧派发不能领取新派发，失败回写也必须匹配当前 queued 版本。领取后仍使用原 lease token 保护进度和结果。无需新增数据库列或授权。
- Sandbox 状态查询连续失败只延后查询；不停止执行、不重发模型请求。只有确认命令退出后才清理 Sandbox；观察窗口耗尽返回 observation_unconfirmed，由 Sandbox 原有 30 分钟硬截止和数据库 32 分钟租约约束。页面仍按原任务查询结果。
- 新代码不自动接管缺少排队版本的旧 Workflow；已有 running 任务保留原租约。部署切换应先核对在途任务；仍处于 pending/queued 的旧任务可手动重新提交原编号。上述实现与本地验证不代表生产部署或付费模型验收完成。
