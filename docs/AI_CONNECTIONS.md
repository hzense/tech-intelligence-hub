# AI 连接与分阶段模型配置

## 当前交付范围

本功能是 [AI 生产技术契约](AUTONOMOUS_SIGNAL_PIPELINE.md) 第 4.1、4.2 节的首批实现，提供管理员连接配置、模型发现／手填、独立能力测试及版本化 Profile。它不启动自动采集，不接收业务文档，不运行 Signal 提取／事实核验／专题生成，也不自动发布。

本批通过独立 PR 交付代码与隔离验证结果，评审、远端 CI 与合并分别确认；尚未执行生产迁移、配置生产 AI 角色／密钥或调用真实供应商。页面部署、服务配置、真实模型兼容性与费用验收须分别确认。

## 管理员使用路径

1. Google 管理员登录后进入 `/admin/ai`。创建连接时填名称、HTTPS API 基础地址、API key、超时、并发、每日估算预算和输入／输出单价。新连接默认停用；主动启用后才能测试。
2. 点击“读取模型列表”，或手动填供应商的完整模型 ID。只显示安全 ID，最多 200 个／12 KB，截断会提示；不支持 `/models` 的兼容服务仍可手填模型。
3. 分别运行“基础连接”“结构化输出”“工具调用”测试。基础连接成功不能代替另两项能力证明。测试仅使用固定哨兵内容；工具测试不执行代码或外部工具。每次点击可能产生供应商费用。
4. 进入 `/admin/ai/profiles`，分别设置提取、独立核验、专题分析的连接、模型、提示词、温度及输出上限。保存配置不会运行任务。
5. 查询 `/admin/ai/tests/<UUID>` 查看测试状态、时间、用量、预算记账和安全结果摘要。网络中断或结果未知时先查询原编号；原编号重试不再次调用模型。

Profile 保存与后续读取就绪检查要求：连接当前启用且存在密钥，所绑定修订未变，同一模型在最近 24 小时通过基础连接和结构化输出测试；若阶段要求工具能力，还必须通过工具测试。修改端点、密钥、预算等任一连接配置会递增修订，原能力证明不再适用。历史 Profile 保留但变为不可用，需重新测试并保存新修订。

## 配置和数据安全

所有页面和 API 独立校验现有管理员会话；写 API 要求精确可信 Origin／Fetch Metadata、JSON 和实际请求体不超过 32 KB。响应禁止共享缓存，页面不被索引。客户端不能提供可信能力结论、预算回执、加密参数、数据库角色或外网调用依赖。

密钥仅在专用密码字段输入，以 AES-256-GCM 信封加密保存：每份凭证使用随机数据密钥，该密钥再由独立服务端根密钥封装，AAD 绑定连接 UUID。数据库保存密文，不保存根密钥；API／页面只返回固定掩码，不返回密文、原值或末尾字符。连接历史只保存不含凭证的配置快照。普通名称、提示词等字段不是密钥存储位置。

更改基础地址必须重新输入密钥，禁止将旧端点的凭证静默转发到新端点。撤销会清空当前密文并停用连接；旧历史不能复原密钥。根密钥环支持不同版本解密，但本批不轮换任何现有凭据。部署密钥环时必须保留仍有密文引用的旧版本；丢失根密钥会使对应凭证不可解密。

供应商请求限制为管理员已配置的 HTTPS 443 域名和基础路径下的 `/models`、`/chat/completions`。服务端域名白名单、全体 DNS 地址公网校验、固定已验证地址连接、原域名 SNI／证书校验同时执行；拒绝私网／保留地址、IP URL、重定向和环境代理。DNS、网络与 SDK 共用 3—20 秒截止，响应最多 1 MiB。只保存固定测试摘要，不保存 SDK 原始响应／错误／Headers，拒绝凭证回显；默认无自动重试或供应商故障切换。防护参考 [OWASP SSRF 指南](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)。

## 预算、幂等与失效

- 每次测试先在数据库连接行锁下登记 UUID、请求指纹、连接修订及预算，再解密并调用。调用前重新检查配置；配置已变或停用则拒绝，调用后发现变化则记录 `stale`，不能作为能力证明。
- 每连接最多 100 次测试／UTC 日，包含模型列表查询；并发 1—3。每日预算跨连接的所有修订累计，不因修改配置归零。不同连接各自记账，不是供应商账户级总预算。
- 生成测试按保守的 8192 输入／128 输出 token 预留，模型列表预留为零。成功后的记账取预留与实际可观察用量估算中的较大值；未知用量、失败和超时保留预算，不宣称未计费。`unknown`／`stale` 不作为成功测试。
- 单价是管理员填写的美元／百万 token 估算，零值须由管理员明确填写。多模型共用连接时应填足够保守的单价，或按计价创建独立连接。不同供应商的推理、缓存、额外收费不保证包含在该估算内；这里的预算不等于供应商真实账单硬上限，仍应在供应商侧设置消费限额。
- 结果不明不得换 UUID 自动重试。同 UUID 相同请求只返回已有记录，不重复外网调用；同 UUID 不同请求返回冲突。数据库 COMMIT 不明时不会继续调用供应商。遗留 `pending`／`running` 超过 60 秒，经列表／详情查询或下次调用检查后标记 `unknown`，保留预留。
- 浏览器会话存储只保留待确认测试 UUID、连接／修订、测试类型与模型 ID，不保存 API key。水合恢复完成前、存储不可用或存在原请求时，禁止静默创建新测试；刷新后可查询原记录。关闭浏览器／手动清除存储不等于供应商请求已取消，创建新测试前仍须核对服务端最近记录。
- 停用／撤销阻止后续调用，不能撤销已经发送的外部请求或供应商账单；在途请求完成后不会给变更后的配置签发能力证明。

## 服务端配置（上线时另行执行）

这里只列变量名称和格式，不保存真实值。不新建本地生产配置文件、不拉取 Production 密钥，所有生产配置通过线上受保护流程完成。Preview 和非 Production 环境不会连接生产 AI 配置库；测试使用单独的隔离数据库或注入的合成 transport，不通过伪造平台变量连接生产。

| 变量                                          | 契约                                                                                                                                                                       |
| --------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `HZENSE_AI_DATABASE_URL`                      | 独立 `hzense_ai_admin` 凭据；明确端口的 Neon pooled URL；TLS 必须开启，目标必须匹配现有 Runtime 的批准主机／端口／库名。不能填 Migrator、Writer、Publisher 或 Runtime 凭据 |
| `HZENSE_AI_KEYRING`                           | JSON 结构 `{"active":"<版本>","keys":{"<版本>":"<32字节随机根密钥的标准Base64>"}}`；根密钥和数据库分开存储，只放服务端 Secret                                              |
| `HZENSE_AI_ALLOWED_HOSTS`                     | 小写域名逗号列表，无空格、通配符、协议或路径；最多 20 个。缺省只允许 `ai-gateway.vercel.sh`，不代表已有 Gateway 账号／密钥／余额                                           |
| `HZENSE_RUNTIME_EXPECTED_HOST/PORT/NAME/USER` | 复用现有批准的 Neon 目标绑定，USER 仍为 `hzense_runtime`；只复用校验契约，实际 AI 数据库连接用户名必须是 `hzense_ai_admin`                                                 |

生产启用顺序：PR 审核及 CI → 受保护迁移并运行精确 Schema 核验 → 最小角色／ACL 审计 → 保存服务端变量并部署 → 管理员添加连接 → 小额真实三类能力测试／未知结果核对 → Profile 保存验收。本文不授权自动执行这些生产操作。

`db/roles/configure_ai_admin.sql` 是独立 opt-in 的授权候选：数据库 owner 身份，已完成 `0013`，事先创建无所有权、无成员关系／设置／旧授权的 `LOGIN NOINHERIT CONNECTION LIMIT 2` 角色；脚本不创建密码，也不自动修复其他角色或 PUBLIC 权限。只授五张 AI 私表的 SELECT、列级 INSERT 和必要 UPDATE，版本历史无 UPDATE／DELETE，无发布、DDL 或业务表写权。应用连接池每实例上限 1，每次取连接复核当前／会话角色和高权限标记；多实例总连接限制仍须在线上验收，不能把池上限当全局容量保证。

## 数据库与代码结构

`0013_ai_configuration.sql` 追加五张私表，不改历史迁移、Signal 内容或公开视图。

| 表                       | 用途                                                              |
| ------------------------ | ----------------------------------------------------------------- |
| `ai_connections`         | 当前修订、名称、协议／地址、启停、预算／并发／超时、加密凭证      |
| `ai_connection_versions` | `(connection_id,revision)` 不含凭证的快照                         |
| `ai_profiles`            | 当前配置与三个阶段的连接／修订／模型／提示词／参数                |
| `ai_profile_versions`    | `(profile_id,revision)` 历史快照                                  |
| `ai_probe_runs`          | UUID 幂等测试记录、配置指纹、状态、估算预算／用量、安全摘要和时间 |

这是受信服务端的 AI 配置存储，不是浏览器直接 SQL 接口，也不是通用任务队列。历史只读由专用服务角色权限保护；它不宣称可以防止数据库 owner 篡改。当前不支持配置物理删除，以保留引用与审计。

- `packages/database/src/ai-config-{contract,crypto,store}.mjs`：输入契约、信封加密、配置事务、测试登记／预算及 Profile 就绪检查。
- `packages/database/src/ai-configuration-catalog.mjs`：独立精确列／约束／索引契约。
- `apps/web/lib/admin-ai-core.ts`、`lib/server/admin-ai*.ts`：服务端目标校验、逐请求鉴权和专用数据库适配。
- `apps/web/lib/ai-provider*.ts`：AI SDK 7 的兼容接口和固定能力测试、有界 HTTPS transport。
- `apps/web/components/admin-ai-*.tsx`：管理连接、模型、版本和测试记录的前端。
- `/api/admin/ai/connections`：GET 列表／POST 新建／PATCH 修订；`/{id}/history` 查询历史。
- `/api/admin/ai/profiles`：GET 列表与动态就绪状态／POST 新修订；`/{id}/history` 查询历史。
- `/api/admin/ai/probes`：GET 最近记录／POST 四类测试；`/{id}` 查询同一记录。

## 验证边界

2026-09-13 本地验收：整仓 2219 项单元、完整 440 项 PostgreSQL 18.4／pgvector 0.8.6 原生集成、19 项构建后认证／HTTP／浏览器测试、28 项全站桌面／移动冒烟全部通过；构建、lint、typecheck、格式、依赖审计、工作流及内容／Seed 校验通过。常规单元命令默认跳过的数据库／构建后场景已通过单独启用的隔离命令验证，不把跳过计为通过。

单元回归覆盖加密随机性与 AAD、配置校验、修订／资格／预算／未知结果；真实 PostgreSQL 集成覆盖精确目录、限制角色、密文快照、事务并发及过期证明；Provider 测试通过合成 HTTPS transport 验证真实 SDK 请求和响应契约，不发送真实供应商请求。Web 回归覆盖匿名拒绝、可信 Origin、请求限制、错误脱敏及缺配置关闭。桌面／移动端已检查水合、表单强制 POST、禁用状态和刷新恢复原编号，无页面异常或横向溢出。浏览器测试没有连接真实供应商／生产数据库，不能计为线上配置保存和真实模型兼容性验收。

隔离构建后测试沿用 `HZENSE_ADMIN_AUTH_INTEGRATION=1`；安装项目 Playwright Chromium 后，可同时设置 `HZENSE_ADMIN_AUTH_BROWSER=1` 启用新增的登录后桌面／移动端检查。这些开关只由测试进程读取，不是应用登录绕过开关。独立审查发现的未水合表单默认 GET 和刷新丢失原请求问题已修复并保留回归。

下一阶段才接入持久任务、批量文档／链接导入、AI 提取／独立核验执行器、来源增量与调度；后续执行器须在调用前使用当前 Profile 资格，不得信任浏览器保存的旧就绪布尔值，也不能以模型能力测试代替内容事实核验。
