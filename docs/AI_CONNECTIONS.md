## 管理员使用路径

1. Google 管理员登录后进入 `/admin/ai`。创建连接时填名称、HTTPS API 基础地址、API key、超时、并发、每日估算预算和输入／输出单价。新连接默认停用；主动启用后才能测试。
2. 点击“读取模型列表”，成功后在唯一的“模型 ID（搜索、选择或手动输入）”框中输入关键词筛选，或点击右侧箭头展开全部模型。支持方向键浏览、Enter 选择、Escape 收起；选择只填入完整 ID，不自动调用模型。没有匹配项、列表读取失败或不支持 `/models` 时仍可在同一框内手填。列表只使用当前连接、当前修订的成功记录，最多 200 个／12 KB，截断会提示；切换连接／修订后清空选值并关闭旧候选，不沿用其他连接的列表。
3. 分别运行“基础连接”“结构化输出”“工具调用”测试。基础连接成功不能代替另两项能力证明。测试仅使用固定哨兵内容；工具测试不执行代码或外部工具。每次点击可能产生供应商费用。
4. 进入 `/admin/ai/profiles`，分别选择提取、独立核验、专题分析的连接。页面自动加载该连接当前修订的模型列表，使用与连接页相同的可搜索下拉选择框；可继续手填列表外的有效 ID。三个阶段预填各自的默认提示词，可编辑提示词及输出上限；不再提供温度输入框，新保存配置统一使用 `0.7`。保存配置不会运行任务。
5. 查询 `/admin/ai/tests/<UUID>` 查看测试状态、时间、用量、预算记账和安全结果摘要。网络中断或结果未知时先查询原编号；原编号重试不再次调用模型。

### 信号生成 Schema 的供应商兼容性

固定哨兵的结构化输出成功，不代表供应商接受完整的候选信号 Schema。GPT6 经 OpenRouter 的真实请求曾先后拒绝 `uniqueItems` 和日期正则中的负向前瞻 `(?!0000)`。出站 Schema 不包含 `uniqueItems`；日期仅使用 `^[0-9]{4}-[0-9]{2}-[0-9]{2}$` 检查格式。组织去重、禁止零年、有效日历日期、原文证据匹配等仍在应用端校验，不因此放宽候选验收。

回归测试递归检查整个 Schema 的限定关键字、对象必填字段与 `additionalProperties: false`，并检查 SDK 最终请求中的日期表达式。依据为 [OpenAI Structured Outputs 支持的 Schema 子集](https://developers.openai.com/api/docs/guides/structured-outputs#supported-schemas)及上述实际供应商错误；本地测试不是真实模型生成验收，也不保证任意其他模型或微调模型均兼容。

Profile 保存与后续读取就绪检查要求：连接当前启用且存在密钥，所绑定修订未变，同一模型已有成功完成的基础连接和结构化输出测试；若阶段要求工具能力，还必须通过工具测试。测试超过 24 小时仅返回非阻断提醒（`readiness.warnings`），不因时间经过自动失效；配置页和生成页建议按需复测，不自动调用模型。每种能力按最近一次匹配的成功完成时间计算提醒，未来时间或未完成记录不作为证明。修改端点、密钥、预算等任一连接配置会递增修订，原能力证明不再适用。历史 Profile 保留但变为不可用，需重新测试并保存新修订；更换模型必须具备该模型的匹配成功记录，不能沿用其他模型的测试。

模型 ID 使用前后端共享校验：最长 200 个 ASCII 字符，允许一个可选的前导 `~`，随后必须是字母或数字，其余字符限字母、数字、`.`、`_`、`:`、`/`、`-`。这兼容 OpenRouter 的 `~` 前缀别名；列表、调用、测试恢复与 Profile 保存均保留完整原值，不删除前缀或悄悄替换成另一个型号。空白、控制字符、查询参数、片段和重复／中间位置的 `~` 仍被拒绝。别名不是固定型号，选择后仍须核对供应商价格与模型能力。

### 分阶段模型与默认提示词

连接内容完全相同的保存（含相同根密钥下重复输入相同密钥）保留原修订与能力证明，不新增版本历史；真实字段或密钥变化仍递增修订并要求匹配的新测试。显式输入凭证时，若根密钥已轮换或原密文不可读，将按当前根密钥重新加密并递增修订，保留凭证维护与恢复能力。版本冲突及安全校验照常执行。测试结果自动保存，测试后无需再点“保存连接”。这不会追溯恢复旧修订的测试资格。

AI 连接页面仅展示按创建时间倒序排列的最近 3 次测试，历史测试、费用审计与能力证明仍在数据库保留，模型列表缓存与资格检查不受展示截断影响。分阶段配置的新建按钮为“创建新配置”，编辑已有配置时为“保存为新修订”。

选择连接时，先复用已读取的同一连接／修订成功列表；没有成功列表才发起一次 `models` 请求。同页三个阶段共享该缓存，不重复读取；加载期间暂时禁用表单，切换连接清空该阶段的旧模型。刷新状态发现连接修订变更、停用或密钥撤销时清空对应模型，连接移除时也清空连接选择。需要新目录时点击“重新读取模型列表”。页面初始化或编辑历史配置不自动请求，选中模型也不运行生成、结构化输出或工具调用测试。

列表失败不会自动重试；结果未知保留原请求编号，通过“查询原编号”读取结果，不创建新编号。连接页与 Profile 页共享这一待确认状态，迟到响应只能释放自身编号，不能清除其他请求。无法安全保存编号时不发请求，仍可手填。列表读取仍计入服务端测试次数、并发和预算门禁，成功目录不等于模型通过保存所需的能力测试。

默认提示词依据 [网站设计](DESIGN.md) 与 [AI 生产技术契约](AUTONOMOUS_SIGNAL_PIPELINE.md) 的范围，集中定义于 `apps/web/lib/admin-ai-profile-defaults.ts`：

| 阶段     | 默认提示词的重点与边界                                                                                                                                       |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 信号提取 | 从材料提取可追溯事件候选，保留来源锚点和事件发生时间，关联有事件证据的人物及组织；不凭职位猜人，不自行核验或发布，不生成日报／周报。                         |
| 独立核验 | 逐项核对原文、来源独立性、人物关联与冲突证据；明确证据不足和不确定性，私有材料不能冒充公开证据，模型结论不能取代服务端资格判断。                             |
| 专题分析 | 只依据输入中已具备当前公开资格的固定 Signal 版本，形成带引用、反证与不确定性的专题洞察；不编造新事实、趋势分数或热度，没有实质变化可报告不更新，不自行发布。 |

三个阶段均将网页、文件和 OCR 内容视为不可信数据，不能将其中的指令当作权限。提示词不能覆盖安全规则、任务授权或输出 Schema；自动发布策略仍由既有产品规则和服务端门禁决定，不由模型授予权限。

新建配置填入默认提示词，编辑已有配置保留原有自定义内容，不批量覆盖历史记录。随机性 `0.7` 是本应用对“适中”的默认约定，新建／保存新修订时使用；历史温度值不迁移。不同模型对温度的支持与语义不同，后续业务执行器仍须处理供应商兼容性，本次不据此宣称真实模型已兼容。

### 供应商预设与接口地址

连接表单提供 Vercel AI Gateway、OpenRouter 和自定义预设；预设只帮助填写基础地址，不自动授权域名、保存连接或调用供应商。页面会按当前部署的 `allowedHosts` 显示是否已授权；服务端白名单及网络防护仍是最终边界。

| 供应商            | 接口基础地址                      | 必须显式授权的域名     |
| ----------------- | --------------------------------- | ---------------------- |
| Vercel AI Gateway | `https://ai-gateway.vercel.sh/v1` | `ai-gateway.vercel.sh` |
| OpenRouter        | `https://openrouter.ai/api/v1`    | `openrouter.ai`        |
| 自定义            | 供应商提供的 HTTPS API 基础路径   | 实际接口的精确域名     |

不要填写完整的 `/chat/completions` 或 `/models` 请求地址：程序会在基础路径后追加相应端点。表单在提交前提示域名未授权、地址格式或端点路径问题；纠正地址须由用户显式操作，不静默更换目的地。切换预设或修改基础地址时，若目的端点发生变化，会清空当前填写的 API key 并要求重新输入；同一地址或仅切到自定义模式不会清空。名称、预算等无关字段保留。

域名未授权时，须由有权限的操作者更新本项目 Production 的 `HZENSE_AI_ALLOWED_HOSTS`，并重新部署后刷新页面。已分别获准使用两家供应商时，该值可为 `ai-gateway.vercel.sh,openrouter.ai`；不要填协议、路径、空格或通配符，也不要在前端或代码默认值里绕过白名单。OpenRouter 基础地址参考[官方快速开始](https://openrouter.ai/docs/quickstart)。

增加白名单并不证明供应商 API key 有效、模型可用或 Profile 已就绪；连接保存和真实能力测试仍按上述步骤分别验收。正在编辑且包含未保存凭据的旧页面不要自动刷新；新部署后由操作者重新打开页面并填写凭据。

## 配置和数据安全

所有页面和 API 独立校验现有管理员会话；写 API 要求精确可信 Origin／Fetch Metadata、JSON 和实际请求体不超过 32 KB。响应禁止共享缓存，页面不被索引。客户端不能提供可信能力结论、预算回执、加密参数、数据库角色或外网调用依赖。

密钥仅在专用密码字段输入，以 AES-256-GCM 信封加密保存：每份凭证使用随机数据密钥，该密钥再由独立服务端根密钥封装，AAD 绑定连接 UUID。数据库保存密文，不保存根密钥；API／页面只返回固定掩码，不返回密文、原值或末尾字符。连接历史只保存不含凭证的配置快照。普通名称、提示词等字段不是密钥存储位置。

更改基础地址必须重新输入密钥，禁止将旧端点的凭证静默转发到新端点。撤销会清空当前密文并停用连接；旧历史不能复原密钥。根密钥环支持不同版本解密，但本批不轮换任何现有凭据。部署密钥环时必须保留仍有密文引用的旧版本；丢失根密钥会使对应凭证不可解密。连接新建的原编号重试也需要解密当前凭证来比较内容；缺失旧版本时会返回 `key_unavailable`，不能把它当成新建未成功或换 UUID 重建，应先恢复正确的密钥环并查询原记录。

供应商请求限制为管理员已配置的 HTTPS 443 域名和基础路径下的 `/models`、`/chat/completions`。服务端域名白名单、全体 DNS 地址公网校验、固定已验证地址连接、原域名 SNI／证书校验同时执行；拒绝私网／保留地址、IP URL、重定向和环境代理。DNS、网络与 SDK 共用 3—20 秒截止，响应最多 1 MiB。只保存固定测试摘要，不保存 SDK 原始响应／错误／Headers，拒绝凭证回显；默认无自动重试或供应商故障切换。防护参考 [OWASP SSRF 指南](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)。

## 预算、幂等与失效

- 每次测试先在数据库连接行锁下登记 UUID、请求指纹、连接修订及预算，再解密并调用。调用前重新检查配置；配置已变或停用则拒绝，调用后发现变化则记录 `stale`，不能作为能力证明。
- 每连接最多 100 次测试／UTC 日，包含模型列表查询；并发 1—3。每日预算跨连接的所有修订累计，不因修改配置归零。不同连接各自记账，不是供应商账户级总预算。
- 生成测试按保守的 8192 输入／2048 输出 token 预留，模型列表预留为零。测试与费用预留共用 `AI_PROBE_OUTPUT_TOKENS`；每日预算及并发限制不变。成功后的记账取预留与实际可观察用量估算中的较大值；未知用量、失败和超时保留预算，不宣称未计费。`unknown`／`stale` 不作为成功测试。
- 预算门禁发生在调用前。如果供应商返回的实际 token 超出预留，事后记账仍会如实增加，因此可能超过当日估算额度；后续请求将被预算门禁拒绝，但已发生的费用不能撤销。该机制是准入控制与估算账本，不是可中途截断供应商计费的硬限额。
- 单价是管理员填写的美元／百万 token 估算，零值须由管理员明确填写。多模型共用连接时应填足够保守的单价，或按计价创建独立连接。不同供应商的推理、缓存、额外收费不保证包含在该估算内；这里的预算不等于供应商真实账单硬上限，仍应在供应商侧设置消费限额。
- 结果不明不得换 UUID 自动重试。同 UUID 相同请求只返回已有记录，不重复外网调用；同 UUID 不同请求返回冲突。数据库 COMMIT 不明时不会继续调用供应商。遗留 `pending`／`running` 超过 60 秒，经列表／详情查询或下次调用检查后标记 `unknown`，保留预留。
- 浏览器会话存储只保留待确认测试 UUID、连接／修订、测试类型与模型 ID，不保存 API key。水合恢复完成前、存储不可用或存在原请求时，禁止静默创建新测试；刷新后可查询原记录。关闭浏览器／手动清除存储不等于供应商请求已取消，创建新测试前仍须核对服务端最近记录。
- 停用／撤销阻止后续调用，不能撤销已经发送的外部请求或供应商账单；在途请求完成后不会给变更后的配置签发能力证明。

连接和 Profile 的新建也支持客户端 UUID：没有 `expected_revision` 表示新建；Profile 更新必须同时携带 `id` 和 `expected_revision`。同编号、同内容的新建请求，只在当前记录仍为 r1 时返回已有记录，不追加历史。不同内容、记录已修改或凭证已撤销时返回 `request_id_conflict`，不能借重试覆盖现有配置。连接重放会在服务端比较当前解密凭证，不把明文或密钥指纹写入历史；Profile 重放重新计算当前就绪状态，不恢复过期能力证明。并发新建由事务级编号锁串行化。

Profile 页的“刷新状态”同时读取配置和当前连接修订。连接修改后，先重新测试，再刷新并保存 Profile 新修订；旧页面状态不能绕过服务端资格检查。所有管理表单显式使用 POST，未水合时不会把输入字段放进 GET 查询串。

| `HZENSE_AI_DATABASE_URL`                      | 独立 `hzense_ai_admin` 凭据；明确端口的 Neon pooled URL，查询参数必须为 `sslmode=verify-full&channel_binding=prefer`；Neon 默认 `require/require` 会被应用配置校验拒绝。目标须匹配 Runtime 批准的主机／端口／库名，不得使用其他角色凭据 |
| `HZENSE_AI_KEYRING`                           | JSON 结构 `{"active":"<版本>","keys":{"<版本>":"<32字节随机根密钥的标准Base64>"}}`；根密钥和数据库分开存储，只放服务端 Secret                                                                                                           |
| `HZENSE_AI_ALLOWED_HOSTS`                     | 必填的小写域名逗号列表，无空格、通配符、协议或路径；最多 20 个。缺失或为空时 AI 后端保持关闭，没有默认供应商授权；使用 Gateway 也须显式填写 `ai-gateway.vercel.sh`                                                                      |
| `HZENSE_RUNTIME_EXPECTED_HOST/PORT/NAME/USER` | 复用现有批准的 Neon 目标绑定，USER 仍为 `hzense_runtime`；只复用校验契约，实际 AI 数据库连接用户名必须是 `hzense_ai_admin`                                                                                                              |

生产启用顺序：PR 审核及 CI → 受保护迁移并运行精确 Schema 核验 → 最小角色／ACL 审计 → 保存服务端变量并部署 → 管理员添加连接 → 小额真实三类能力测试／未知结果核对 → Profile 保存验收。本文不授权自动执行这些生产操作。

`db/roles/configure_ai_admin.sql` 是独立 opt-in 的授权候选：数据库 owner 身份，已完成 `0013`，事先创建无所有权、无出向成员关系／设置／旧授权的 `LOGIN NOINHERIT CONNECTION LIMIT 2` 角色；脚本不创建密码，也不自动修复其他角色或 PUBLIC 权限。五张 AI 私表只按显式列白名单授予 SELECT、INSERT 和必要 UPDATE，未来新增列不会自动可读；版本历史无 UPDATE／DELETE，无发布、DDL 或业务表写权。提交前再次核对角色、成员关系、有效权限、直接 ACL 和 grant option，发现超额权限则整个事务回滚。

PostgreSQL 16+ 的非超级用户 `CREATEROLE` 创建者会收到一条由 bootstrap superuser 授予的管理关系，创建者不能自行撤销。在 Neon 中只接受与 Runtime 相同的精确入向边：`hzense_ai_admin` 授予 `neondb_owner`，grantor 为 `cloud_admin`，`ADMIN=true`、`INHERIT=false`、`SET=false`；其余入向边和所有出向边拒绝。它不会让 AI 角色继承创建者权限，但 `neondb_owner` 仍可管理／重新授予该角色，因此这是明确接受的云管理员控制边界，不是针对管理员的安全隔离。[PostgreSQL 官方说明](https://www.postgresql.org/docs/18/role-attributes.html)

`db/roles/create_ai_admin.sql` 是独立的 Neon 凭据创建候选，须由管理员在已核对的生产 `main`／`neondb` 以 `neondb_owner` 提交。它将 `createrole_self_grant` 在事务内清空，并固定 `password_encryption=scram-sha-256`，仅接受上述精确管理边；不尝试撤销系统保留的边。随机密码只作为查询结果返回，事务临时表提交即删除，不写入本项目脚本或日志证据；平台查询结果及审计留存仍由平台策略控制。仅在 `COMMIT` 成功后使用结果，不重复运行或刷新丢失结果。若角色已存在，立即拒绝，不轮换密码，也不附带五张 AI 表授权。数据库分支身份仍需从 Neon 页面核对，SQL 中的数据库名／角色守卫不能独立识别分支。

授权前和提交前均检查其他可连接数据库的有效 CONNECT／CREATE／TEMPORARY，包含通过 PUBLIC 获得的权限；`NOINHERIT` 不能隔离 PUBLIC。仅接受与 Runtime 相同的精确 Neon 保留库形态：`cloud_admin` 所有、连接限制 `-1`，`postgres` 的 NULL ACL／PUBLIC CONNECT+TEMPORARY，或 `template1` 的模板标志／显式 ACL／PUBLIC 仅 CONNECT；不得有目标角色直接授权、grant option 或 CREATE。普通业务库不在豁免内，发现异常只拒绝，不改其 ACL。

提交前复核只覆盖当时可见的权限状态，不锁住其他数据库 ACL，也不阻止后续管理员改权，维护期间仍须冻结 DDL／ACL。回归中的授后漂移由同事务插入授权模拟，并非双会话竞争；保留库测试投影名称／模板标志、仍按真实 OID 核对权限，不代替 Neon 实际验收。

应用连接池每实例上限 1，每次取连接复核当前／会话角色和高权限标记；多实例总连接限制仍须在线上验收，不能把池上限当全局容量保证。

## 数据库与代码结构

`0013_ai_configuration.sql` 追加五张私表，不改历史迁移、Signal 内容或公开视图。

| 表                       | 用途                                                              |
| ------------------------ | ----------------------------------------------------------------- |
| `ai_connections`         | 当前修订、名称、协议／地址、启停、预算／并发／超时、加密凭证      |
| `ai_connection_versions` | `(connection_id,revision)` 不含凭证的快照                         |
| `ai_profiles`            | 当前配置与三个阶段的连接／修订／模型／提示词／参数                |
| `ai_profile_versions`    | `(profile_id,revision)` 历史快照                                  |
| `ai_probe_runs`          | UUID 幂等测试记录、配置指纹、状态、估算预算／用量、安全摘要和时间 |

这是受信服务端的 AI 配置存储，不是浏览器直接 SQL 接口，也不是通用任务队列。历史只读由专用服务角色权限保护；它不宣称可以防止数据库 owner 篡改。当前不支持配置物理删除，以保留引用与审计。

- `packages/database/src/ai-config-{contract,crypto,store}.mjs`：输入契约、信封加密、配置事务、测试登记／预算及 Profile 就绪检查。
- `packages/database/src/ai-model-id.mjs`：不依赖 Node 的模型 ID 共享校验，供服务端、数据库配置契约和浏览器测试恢复共同使用。
- `packages/database/src/ai-configuration-catalog.mjs`：独立精确列／约束／索引契约。
- `apps/web/lib/admin-ai-core.ts`、`lib/admin-ai-service.ts`、`lib/server/admin-ai*.ts`：服务端目标校验、逐请求鉴权、共享命令分发和专用数据库适配；分发器依赖只由受信服务端注入，不接受客户端覆盖。
- `apps/web/lib/ai-provider*.ts`：AI SDK 7 的兼容接口和固定能力测试、有界 HTTPS transport。
- `apps/web/components/admin-ai-*.tsx`：管理连接、模型、版本和测试记录的前端。
- `apps/web/components/admin-ai-model-picker.tsx`：单一可编辑模型组合框；候选搜索、鼠标／键盘选择和手填共享同一模型值，组件本身不发起请求。
- `apps/web/lib/use-ai-model-discovery.ts`：Profile 页按连接修订复用模型目录，选择时有界读取，未知回执保留原编号并通过 GET 恢复。
- `apps/web/lib/admin-ai-profile-defaults.ts`：三阶段中文默认提示词及新保存配置使用的适中随机性常量。
- `/api/admin/ai/connections`：GET 列表／POST 新建／PATCH 修订；`/{id}/history` 查询历史。
- `/api/admin/ai/profiles`：GET 列表与动态就绪状态／POST 新修订；`/{id}/history` 查询历史。
- `/api/admin/ai/probes`：GET 最近记录／POST 四类测试；`/{id}` 查询同一记录。

## OpenRouter 多模型兼容（2026-09-20，本地开发，未部署）

- 能力测试及候选生成共用 `apps/web/lib/ai-model-compatibility.ts`，调用前通过原有 DNS 固定、域名白名单、响应大小与截止时间保护读取 `/models`；不缓存密钥，不依赖写死的模型名称。目录缺失或不支持所需能力时停止，不降级为普通文本生成。
- 结构化调用要求目录声明 `response_format` 和 `structured_outputs`，发送 `provider.require_parameters: true`，筛选支持请求参数的端点。目录声明不保证业务验收，端点能力仍可能变化。
- OpenRouter 不发送统一温度，使用供应商默认值；其他 OpenAI-compatible 连接仍使用已保存温度。2026-09-25 调整为优先关闭可选推理（目录 `mandatory=false` 时发送 `enabled:false`）；强制推理模型使用支持的最低档位，始终 `exclude:true`，不返回或保存独立思考内容。不声称所有模型都能取消内部推理或相关计费。
- 供应商 Schema 保留对象、字段、必填、枚举、数组项及可空结构，将字数、数量、日期正则等非通用约束转为描述；本地仍严格校验 80 字标题、500 字摘要、最多 5 条及逐字原文证据。不把供应商成功等同于候选有效。
- 2026-09-25 起代码允许配置最大 50,000 输出 tokens，新建提取配置默认 50,000，其余阶段默认 2,048。既有配置及任务快照不自动升级，须显式保存配置新修订。输入使用本地 `o200k_base` 估算，完整请求预算上限 100,000 tokens；不同模型的真实分词和账单以供应商为准。目录明确声明的上下文／输出能力不足时停止，不擅自压低配置或切换模型。
- 不增加每日预算、不自动重试。`finish_reason=length` 单独归类为 `generation_output_truncated`，保留用量、不保存截断结果；强制推理仍可能占用输出额度，50K 也不保证任何资料一次成功。能力测试仍有独立的 3–20 秒截止时间与 2,048 输出额度，不随生成额度扩大。
- 回归矩阵覆盖 OpenAI、Anthropic、Gemini、DeepSeek、Qwen、GLM、Kimi 的合成目录及真实 SDK 请求报文，**不是付费模型实测或生产验收**。无结构化能力的模型不会被虚假标记为支持。
- 官方依据：[结构化输出及端点路由](https://openrouter.ai/docs/guides/features/structured-outputs)、[推理能力与输出额度](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens)。
