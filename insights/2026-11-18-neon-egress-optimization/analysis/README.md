# 情景复算说明

运行：

```sh
python3 insights/2026-11-18-neon-egress-optimization/analysis/scenarios.py
```

只使用 Python 标准库，读取昨日已归档的 `calculations.json` 和 `routes.csv`，写入本目录 `scenarios.json` 与 SVG。无需凭据、网络、生产数据库或新增依赖。

数据及方法：

- 基线目录字节数来自 2026-11-17 的 JSON 文本长度；条数 184 来自同日 SQL 聚合观察。两者都不是今天重测值。
- 只选取同一 12 小时窗口的资源/人物详情 1,028 次请求，假设它们每次都触发一次目录读取。312.36 MB 是条件基线，不是已归因的实测账单。
- “每页关联 5、10、20、50 条”为假设，使用全目录平均记录大小估算；没有声称这些是线上实际关联数。
- 缓存模型假设命中率为 50%、80%、90%、95%，且每请求额外读取 16,384 字节版本元数据。元数据大小和命中率均未实测；权限查询、协议开销、报告、其他路由和新版本并发填充不在模型中。
- 两组情景是替代估算，不能把节省比例直接相加；不产生全站或月账单预测。确定性算术没有统计采样分布，不构造虚假的置信区间。

脚本检查输入单位/目录大小、路由唯一性与请求总数，并核对基线及情景单调性。字段投影还没有真实样本测量，因此不填入虚构收益比例。
