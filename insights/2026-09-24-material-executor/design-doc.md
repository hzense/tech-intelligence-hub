# 通用材料核验执行器

状态：开发中；读者：维护者与管理员。目标是候选页只确认、不填写 JSON，同时让确认和签名可追溯。

## 目标与边界

[事实] PR #157 的报告接收不等于已存在实际核验执行器。本批补充私有提案、不可变人工确认、规则准备与独立执行入口。保留原候选、账本及现有发布门禁。无生产迁移、角色授权、付费 AI 或公开发布操作。

## 方案取舍

| 方案                                   | 可用性                         | 信任边界                                             |
| -------------------------------------- | ------------------------------ | ---------------------------------------------------- |
| 模型直接输出六个 true 并由 Web 自签    | 少一次确认                     | 无法证明使用许可，且私钥与提案进程共存，不采用       |
| 规则/AI 提案，人工确认，独立执行器签名 | 多一次明确确认，证据不足仍阻塞 | 用户已选择；提案不是核验报告，私钥仅在受保护运行环境 |
| 外部专业核验服务                       | 可提供独立调查                 | 当前无已配置服务，保留协议兼容，不假定存在           |

## 数据流

`补证请求 → 规则准备 → candidate_material_proposals → 页面展示六项声明及每段原文 → candidate_material_approvals → GitHub 独立执行器 → 同 URL 实时原文复查 → 签名报告 → 管理员确认登记`

0024 独立增加两张追加式私表，不修改已经合并的 0023。审批身份来自会话；客户端只提交请求/提案标识、摘要及 consent，不传可信结论。审批最长 24 小时；过期后新 UTC 日准备新的提案再确认，旧记录不覆盖。

执行器只处理指定 request 与 approval 两个 UUID，首次读取与签名前回读均须匹配同一确认。服务 token 只发送固定 hzense.com 接口；来源抓取使用公共 DNS 校验及地址固定，拒绝重定向。解析只接受受限 HTML/文本，子进程不继承私钥等秘密。抓取完成后重读后台审批，变化则不签。签名最长 60 秒、抓取快照最多允许 5 分钟旧，不自动重试或公开发布。新报告入库在运行锁内重新核对最新人工确认与计划、所有者、提案摘要及有效期，历史报告重放保留原接收时间。

当前准备器不调用模型，仅复用已提取事实和现有目录。新组织类型、别名冲突、缺少人物/日期/领域/公开引用均阻塞；不会臆测身份、日期或许可。后续 AI 提案必须另接持久化预算与租约，不允许借此绕过现有费用规则。

## 发布与回滚

先代码评审和 CI，再确认 0023/0024 精确待迁移计划、备份及最小 ACL。Web 只持有公钥；GitHub 的 material-verification 环境保存私钥，限制 main 并设置保护。Web dispatch token 只能操作指定仓库 Actions，不能使用全权限管理员 token。开关默认关闭，配置完成再验收合成资料。关闭开关保留只读历史，不删除审计表。

## 风险、反面观点与未解决项

- 人工可能盲目点击：页面明确显示全部六项声明和具体 URL/摘录，并再次确认；来源可达不是许可证明。更高风险内容仍应由专业核验方审核。
- 规则保守会留下待补全：接受这个限制，不伪造人物/组织类型来消除提示。规则命中不是自动事实核验。
- 签名私钥或 service token 泄露：独立环境、最小授权、不记录正文或凭据；上线配置时需核对权限与公钥身份。
- 并发确认或提交超时：不可变审批和计划摘要保持同一对象；报告摄入依赖既有幂等约束，未知结果不声称成功。
- GitHub 任务未运行/审批过期：确认已持久化但尚未签名，页面不显示已核验；可重新读取状态，不能重复生成付费任务。
- [未验证] 生产迁移、真实角色授权、线上确认到签名登记闭环；这些不能由本地测试替代。

## 自评

正确性与安全边界由协议、存储、路由、执行器负向测试与浏览器确认测试覆盖。可运维性有条件通过：生产凭据、环境保护、精确迁移和在线验收仍待实施。成本为零新增模型调用，但 GitHub 运行资源按现有账户规则计算。
