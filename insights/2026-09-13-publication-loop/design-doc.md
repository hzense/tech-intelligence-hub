# 受限公开发布设计与自审

## 目标与非目标

目标：管理员能够将已经核验、组装且仍符合当前资格的候选发布；能够在发布总开关关闭或原运行到期后撤回；网站列表、详情、关联信号及信号搜索同步遵守当前资格。

非目标：新采集任务、模型接入、手动上传、自动核验事实、历史 Signal 批量补人物、生产迁移及切换。旧私有 Adapter 保持私有语义。

假设：核验服务及核验记录写入者可信；数据库 owner/迁移账号不属于受限 Publisher 威胁边界。调用者不得提供数据库连接、正文、核验布尔、人物身份覆盖或执行回调。原核验有效期约束新发布，不能机械地使所有已发布内容 24 小时后过期。

## 方案比较

| 方案                                  | 优点                                                   | 代价与风险                                                                 |
| ------------------------------------- | ------------------------------------------------------ | -------------------------------------------------------------------------- |
| 独立物化公开表与 Outbox 消费者        | 索引优化、异步重建空间较大                             | 多一个消费者与检查点；旧事件、延迟撤回、重复写需额外处理；仍需读时资格过滤 |
| 新公开许可 + 同一实时安全视图（采用） | 发布与公开资格原子；网站和搜索无需手工同步或第二份正文 | 当前依赖 seal 比较有查询成本，大数据量前需要真实负载验证                   |

没有复用旧 `search_documents` 存储新版本正文：旧 Seed 同步以全表期望集删除其它行，且旧 Reader 的直接列权限不能表达新资格。

## 数据与事务

```text
原候选 → 核验记录 + 数据库依赖 seal → 已封存核验组装
                                              ↓
管理员会话 → 严格标识命令 → 受控 Publisher → 新版本 + Head/Outbox + 公开许可
                                              ↓
                            current_public_signals → 网站 / 信号搜索
```

发布必须绑定完整核验／组装／版本链，并在依赖锁等待及延迟约束之后核对时限和运行资格。数据库守卫还检查精确克隆和运行门禁，不能仅依赖 JavaScript 的调用顺序。旧核验不回填 seal，不能被迁移过程默认为已获新许可。

依赖 seal 使用 PostgreSQL JSONB 原值，覆盖原版本、事件身份依据及其旧版本证据、来源、证据、人物／组织和领域。变化永久锁存失效；恢复字段原值不会重新公开，需要新的核验和受控发布。

撤回独立校验管理员及版本 CAS，不要求原自动任务继续运行。幂等重试返回旧回执，并另外读取 `current_public`；历史成功不等于现在可见。

## 安全与兼容

- API 自己校验 Google 管理员会话、精确 Origin、JSON 类型、实际请求体不超过 4096 字节、固定字段集合。
- Publisher 独立凭据，拒绝迁移角色；共享来源和控制表不授 UPDATE，锁通过受限能力函数完成。
- Runtime 只读显式公开 DTO，不返回证据摘录、定位器、核验报告、原始 metadata 或任务租约。
- 新模式缺失数据、资格失效或数据库故障均不回退 Seed。旧搜索的所有 Signal 结果被排除，避免同 ID 撤回后由旧索引“复活”。
- 使用请求时动态读取而不是缓存公开正文。旧版仍为默认，不自动执行生产迁移或改环境。

## 自审结论与剩余风险

逐项检查：目标可追溯；跨层契约明确；两种可行方案比较；发布／撤回失败路径；凭据与数据库角色隔离；生产步骤单独授权。

反向场景包括：伪造 `verified`、绕过 API 直写许可、过期核验与等锁后过期、原总开关关闭、重复请求、撤回后旧请求重放、人物和来源元数据变化、恢复原值、读模式拼错以及数据库不可用。

仍需上线阶段实测：生产最小 ACL 与连通性、真实运行创建及核验输入、发布／撤回业务验收、数据规模下的视图延迟。历史雷达快照没有版本绑定，在新读模式下暂停使用，等待后续趋势重算开发，不将旧指标伪装为新版本分析。
