状态：本地代码与构建验证通过；隔离 PostgreSQL 集成、PR/CI 与生产启用另验。

目标：整理当前状态，交付信号筛选、雷达首页、资源人物目录，以及可配置采集和专题洞察任务。

- [设计与验收](design-doc.md)
- [来源与代码依据](sources.md)

本批不删除旧日报、周报和洞察正文，不自动公开候选，不调用生产 AI，不假称新增生产权限已经配置。

## 五项交付对照

1. 进展与验收归档：PROGRESS.md 顶部增加当前状态，既有生产证据保留原文并区分代码、迁移、授权和真实验收。
2. 信号：当前公开/历史档案分开，支持 URL 可复现的时间、领域、专题、人物、组织、关键词交集筛选，服务端分页与列表/时间线/领域分组。
3. 雷达：主页为领域观测及近期信号 TOP 10。仅有事件时效分可复算；综合热度、产业涨跌没有充分依据时明确留空，绝不以旧档案补满。
4. 资源：人物与组织由当前公开信号关系构建，按近 30 日不同信号数排序；共同出现不冒充任职关系。
5. 后台：来源链接配置可手动或按 UTC 每日/每周触发，持久导入并建立私有生成任务；专题洞察冻结当前公开信号版本，独立预算、长任务、人工阅读确认和撤回。所有定时入口默认关闭。

## 本地验证与上线边界

- Web 类型检查、ESLint、生产构建与全量 Node 测试通过；数据库 Vitest 为 82 个文件通过、23 个文件因本机无 PostgreSQL 跳过（2350 项测试通过）。迁移和角色隔离的 PostgreSQL 集成测试已接入 CI，但本机未执行，不冒充已通过。
- 数据库代码新增 0026、自动化私有角色和专题公开只读角色；未在生产执行迁移、角色脚本、配置凭据或启用开关。
- 采集仅处理管理员列出的固定公开 URL，不是开放网络爬虫、RSS 发现或可靠的全网覆盖。导入成功只创建私有候选任务，候选仍须原有审核与人工发布。
- 每个专题报告要求至少两条当前公开信号并逐节引用，源信号撤回或版本变化后报告停止公开。模型失败/派发未知不自动重试付费调用。
- 上线需要独立备份、只读预检、0026 迁移及结构核验、最小权限角色核验、生产 Secret/预算/开关配置、Preview/Production 部署和真实单次验收；当前本地构建不代表已上线。
