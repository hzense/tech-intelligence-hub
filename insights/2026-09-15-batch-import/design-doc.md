# 批量导入中心设计

## 1. 问题与背景

[事实] 第一阶段是已部署的只读信号工作台，不存在上传、批次或解析入口；第二阶段必须覆盖文件、链接及混合批次，而不是一个“上传成功”的页面壳。[R1、R4](sources.md#仓库事实)

本阶段要解决五个问题：

1. 如何在接收前准确提示格式、数量、容量和能力缺口？
2. 如何确认原件已持久接收，并把每个输入关联到不可替换的文档版本？
3. 如何在不泄露私有文档和凭证的前提下抓取、解析、OCR？
4. 如何支持部分失败、关闭浏览器继续处理、取消与可对账重试？
5. 如何把解析结果交给后续 AI 阶段，同时不绕过公开证据和人物资格？

## 2. 目标与非目标

[事实] 完整阶段 2 包含 PDF、DOCX、Markdown、TXT、HTML、CSV、XLSX、扫描 PDF、PNG／JPEG OCR。旧 DOC、宏文档及压缩包返回转换提示，不执行宏、脚本或表格公式。[R2](sources.md#仓库事实)

目标：管理员提交混合批次，逐项查看接收／解析／错误／重试，原件私有，输出有页码、段落、单元格或 OCR 区域定位。只对服务器已确认接收并落库的项承诺关闭浏览器后继续处理。

非目标：本阶段不实现事件核验、自动来源调度、AI 生成、公开资格、发布／撤回、索引同步或网站数据源切换；分别属于后续阶段。产品已有“生成并发布／仅预览”意图在最终入口保留，接收文件本身不是发表授权，也不启用生产开关。

## 3. 约束与待确认项

- [事实] 现有 Neon、Google 管理员认证、独立 AI 配置与发布权限边界保留。不能借 owner、migrator、AI Admin、Publisher 或现有只读角色执行导入写入。[R1、R6](sources.md#仓库事实)
- [实施约定] 主稿和校验包统一明确为 **25 MiB／200 MiB**，即 `25 * 1024 * 1024` 与 `200 * 1024 * 1024` 字节；UI 和服务器必须显示同一精确单位，仍需上线前压测。每批最多 20 文件、100 非空链接行，单文档最多 300 页。硬防滥用上限与业务配额分开，不静默截断。
- [推断] 最终需要独立私有原件存储和线上隔离解析环境；单个 Next.js 请求不足以承担全部格式、安全隔离和可续跑要求。[R2、R3、E1](sources.md)
- [待确认] 推荐 Neon＋私有 Blob＋隔离 Worker 的组合；具体资源、地区、保留期限、OCR／模型供应商和费用上限另行确认。未确认时只写供应商独立代码及隔离测试，不创建付费资源。
- [待验证假设] 线上 Worker 能满足解析内存、压缩解包、页面、耗时、网络和费用限制；不能仅凭平台产品说明认定通过。测试不要求用户在本地运行采集／上线工具。

## 4. 方案比较与建议

| 方案                                                               | 优点                                                         | 主要代价／风险                                                                      | 结论                                        |
| ------------------------------------------------------------------ | ------------------------------------------------------------ | ----------------------------------------------------------------------------------- | ------------------------------------------- |
| A：现有 Neon 存状态，Vercel 私有 Blob 存原件，独立隔离 Worker 解析 | 复用已有身份／部署，原件和业务状态分开，允许逐步替换解析服务 | 必须补对象确认、租约、回调鉴权、网络隔离及费用账本；Blob 与数据库不能跨服务原子提交 | 推荐，组合待确认；Worker 运行时不在本次锁死 |
| B：Neon＋外部私有对象存储＋外部任务服务                            | 独立队列和解析能力，较少受 Web 运行时限制                    | 新增供应商、凭据、跨服务运维与数据驻留审批；本项目尚无集成                          | A 无法满足限制时的替代路径                  |
| C：全部文件经 Web 请求上传并同步解析                               | 原型代码较少                                                 | 大文件传输、复杂解析隔离、超时和续跑难满足设计                                      | 不作为完整实现                              |

[推断] A 的对象存储适配器应只提供签发受限上传、核对具体对象、受控读取和按保留策略清理；不要把供应商 URL 当数据库对象身份。E1 支持直传边界，E2 支持私有能力，均不替代对象版本／回调真实性测试。[官方依据](sources.md#官方平台资料)

### 2a 接口

`validateImportManifest(input, { capabilities })` 是纯函数，输入文件声明与逐行 URL，不读取文件、网络、环境或数据库。接口和错误码以[包文档](../../packages/ingestion/README.md)及类型声明为准。

- 逐项保留文件序号、用户输入标识和链接物理行号，合法项与非法项均有结果。普通业务超限仍明确返回整批错误；极端超大输入返回显式硬上限错误，不返回局部“成功”。
- 客户端 MIME／后缀／大小／页数只作声明。空 MIME 或通用二进制声明不证明安全。`requiresOcr` 只能提前暴露扫描能力缺口，`false` 或省略不免除实际扫描检测。
- URL 只接受无凭证、HTTPS／443、公网域名形式；拒绝字面 IP、控制字符和本地名称。保留查询顺序及参数，去片段仅用于本批重复提示；不等同抓取去重，更不是 SSRF 防护完成。
- 格式、URL 抓取和 OCR 能力由调用方显式提供，缺失即拒绝。本次测试能力是夹具，不可在生产写死为全部可用。
- 返回 `valid` 仅是声明在该能力快照下合规。输入标识不等于持久化 item ID，重复标记不等于已导入，结果应只在管理员私有上下文使用，禁止日志记录含查询参数的完整 URL。

## 6. 后续持久化与状态边界

[推断] 下一次迁移应独立建立以下职责，不给现有只读或公开 Runtime 增权：[R3、R4](sources.md#仓库事实)

| 职责                       | 必要约束                                                                                       |
| -------------------------- | ---------------------------------------------------------------------------------------------- |
| 批次／输入项               | 管理员归属；请求 ID＋内容指纹幂等；冻结的配置、限制、意图与预算；同键不同内容冲突              |
| 文档／不可变版本／输入关联 | 私有对象身份、具体对象版本、实测哈希／大小／类型、原始／规范 URL、确认时间；跨批复用先检查归属 |
| 解析运行／尝试／片段       | 配置及解析器版本、租约、递增 fencing、定位、有界正文；成功结果不可覆盖，重试新 attempt         |
| 审计／用量账本             | 接收、确认、下载、取消、清理；按批次与全局原子预留／结算，未知 OCR 结果不盲目付费重试          |

目标状态流：`声明合规 → 批次已持久化 → 对象已核对 → queued → running → completed / partial_success / failed / cancelled`。声明合规之前没有 batch ID；上传中、已存对象、已接收、已解析、生成 Signal 和已公开是不同状态。

Worker 用短事务领取及提交，网络、解包和模型调用在事务外。取消及超时接管增加 fence，旧 Worker 即使返回成功也不能写回；关闭浏览器不改变已提交任务。任务表只为导入服务，不复用受限发表任务或 AI 连接探测表。

**来源表特别约束：** 现有 seal 对 `sources` 整行计算，并有更新失效触发器。采集游标、ETag、last_seen 或解析状态放在独立私表；向 `sources` 增加列本身也可能改变已有 seal。不要通过放宽 seal 来方便采集。[R5](sources.md#仓库事实)

## 7. 安全、成本与故障

以下都是后续交付要求，不是本次纯校验包已提供的防护：

- API：每次会话／归属／固定站点及写入 Origin 校验；真实流式字节上限、读取超时、限流；不信任 Content-Length 或客户端能力位。
- 原件：只签发短期、单对象、单操作、大小／类型受限权限。服务器核对回调签名、归属、对象版本、实测字节／签名／哈希，不能相信浏览器完成回执。对象存储成功而事务失败时保留可回收孤儿记录，不能假装两者原子成功。
- 抓取：DNS 全结果、每次重定向、最终连接地址都必须检查；连接固定已核对地址，限制跳转／字节／时间。不向任意站点转发 Cookie、管理员会话或 AI Bearer 凭据。不直接复用带供应商凭证的 AI transport。[R6](sources.md#仓库事实)
- 解析：受限环境内运行、无数据库／AI 全权 Secret，默认禁止外部网络、宏、脚本、Office 外部引用及公式执行；独立限制 CPU／内存／解压字节／页面／正文／单元格数。CSV／XLSX 保留 sheet／行列上下文；公式缓存不能冒称重算值。
- 私有材料：原件名、私有 URL、签名查询和正文不得进入公开投影。任何外部 OCR／AI 传输先确认供应商与隐私授权；私文档没有独立公开佐证时，后续保持 `needs_public_evidence`。
- 重试和费用：调用前留预算，调用后结算。供应商返回未知时先对账；新 attempt 复用确定输入版本和检查点，不复用过期授权。规模增至十倍时，批次上限不随之放宽，应测队列滞留、数据库池和解析并发／日预算。
- 清理：具体保留天数待确认；未完成上传可按策略清理，有已发表证据引用的版本不能按普通临时文件删除。取消未完成项不撤回已发表事件。

## 8. 验证、迁移与发布门禁

本次 2a 要求纯函数恶意输入／边界／能力／重复回归、类型声明契约检查、lint、格式和 workspace 集成检查；不得声称进行了浏览器上传或生产导入验收。

2b 必须同步迁移 checksum、Drizzle、精确 catalog／verifier 和原生 PostgreSQL 测试。测试应覆盖默认 ACL 泄漏、越权读写、并发幂等、对象伪造、跨批复用、过期 Worker 提交、取消和预算竞争；不得跳过 exact-schema 检查。

2c–2e 要求实际组件／Next.js 鉴权与私有存储／隔离 Worker 端到端测试、全部格式夹具和恶意文件、断网／重启续跑及成本对账。生产配置审批、迁移、部署、非空真实批次验收分别记录；任何缺项都不完成阶段 2。

回滚本次 2a 只涉及未接线的包与文档，没有业务数据回滚。后续物理迁移优先增量兼容，不擅自删列或表；公开数据源与发表开关保持原值，不新增恢复演练。
