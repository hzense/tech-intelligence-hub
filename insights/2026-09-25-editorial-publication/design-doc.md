# 四项确认发布设计

## 决策

新增独立 editorial 人工确认发布通道，不改写旧 qualified 通道的签名和证据语义。候选页由四项表单和“确认发布”主按钮组成，原资料折叠辅助展示。保留登录、归属、真实日期、实时领域目录和不可变原文；移除旧核验业务条件对新发布的依赖。

## 数据流

原候选／历史补全 → 四项表单 → 管理员确认 → 追加修订 → 最新公开视图 → 列表／详情／搜索。

所有写入需服务器复算材料指纹、校验原候选标题摘要及明确确认；请求 UUID 幂等，预期修订进行 CAS，事务锁串行化同一候选。手填姓名只是管理员声明，不能生成虚假 verified 关系或独立签名报告。撤回追加新修订，公开查询先选最新修订再过滤 publish。

## 权限与边界

独立 writer 仅读取必要生成、领域和修订列，并追加修订；reader 只读公开视图。私有原文、导入地址、owner 和原任务 ID 不进入公开 DTO。默认关闭生产开关；迁移、授权、配置和内容发布必须独立验收。

不在本批实现 AI 自动采集、自动发布、人物消歧、正式实体关系、专题洞察及热度评分；不调用模型或回写历史费用。

## 风险和缓解

| 风险                 | 处理                                                     |
| -------------------- | -------------------------------------------------------- |
| 人工输入有误         | 显示明确的管理员确认依据，允许修订和撤回，不声称独立核验 |
| 重复点击／提交超时   | UUID 幂等、结果不明保留原请求、同候选 CAS                |
| 公开内容泄漏私有原文 | DTO 仅含候选标题摘要和四项信息，原件及引用不投影         |
| 搜索缓存复活撤回记录 | 只合并实时可见 Signal，丢弃持久索引旧 Signal 命中        |
| 删生成任务后无法撤回 | 当前已发布候选禁止删除原任务，先撤回                     |
| 旧方案错误地标为通过 | 新表和新依据，不写旧 attestations／verified 记录         |
| 开关回滚             | 关闭后隐藏本通道所有公开信号；保留记录，文档明确影响     |

## 自评与验收标准

- 四项有一项缺失不能发布；手填补齐后无需其他证据门禁。
- 未授权、跨 owner、错误材料、停用领域、陈旧修订被拒绝。
- 同请求重试无新增记录；并发只能有一个预期修订成功。
- 发布、刷新回读、更新、撤回均可追溯，原 AI 结果和预算不变。
- 默认关闭，启用缺配置时不误报成功；公开读取故障不能回退到已撤回缓存。
- 合成浏览器与隔离数据库测试覆盖上述链路，生产验证另行授权。

## 复审结论

独立复审发现三项问题，现已修复：历史幂等回执必须再读取最新状态（防止别人已经撤回仍显示已发布）；已停用／更名领域必须可见可移除；请求 30 秒超时后释放界面但保留原请求，不能自动重发。补充用真实 React 组件驱动的合成浏览器测试并通过复审。

配置复核统一 writer／reader 的生产环境、物理目标、专用身份及 TLS 限制；开关纳入构建缓存键。验证结果见[交付说明](../../docs/EDITORIAL_PUBLICATION.md#本地验证)。本设计将管理员声明与独立核验区分，未用简化 UI 绕过旧核验语义。
